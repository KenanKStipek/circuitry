- **Saved state holds each loop's final pass once.** A named loop's `last` is written to `--out`, `--print` and the `--live-state` mirror as a reference to the pass it aliases, `"last": {"$ref": "iter_<N>"}`, instead of a second full copy (nested loops copied it again at every level: 22–52% of a large `state.json`). Run-time reads of `prime.<loop>.last` are unchanged, and a saved state passed back with `--state` (or as `initial_state`, or opened in the TUI's Runs view) has its references relinked, so `last` reads the same as in the run that wrote it. State files that hold full `last` copies still load. (#220)
- **`--live-state` coalesces its writes and keeps file I/O off the run.** The mirror used to re-serialise and rewrite the whole state on every write, in the thread that made it (and, for `Store.set`, under the lock tree-flow branches share). It now writes the initial snapshot up front (an unwritable path still fails the run), then records each write and returns; a writer thread serialises the newest state at most once every 0.5 s (`LIVE_STATE_INTERVAL_SECONDS`) and writes the file outside the store lock, and a final write when the run ends — success or failure — makes the mirror equal the `--out` state (it used to miss what was recorded after the last effect, such as `runtime.last_run.completed_at`). On a synthetic nested-loop run with 800 prompt calls, mirror writes dropped from 802 (1.56 GB, 5.8 s spent in the callback) to 7 (14.5 MB, 12 ms). (#220)
