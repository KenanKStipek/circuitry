- **Per-run overrides for the three complexity switches.** `cof run --scoring/--no-scoring`, `--routing/--no-routing`, and `--decompose/--no-decompose` force `runtime.complexity.{scoring,routing,decomposition}.enabled` on or off for a single run, ranking above `--profile` and the orchestration/config the same way `--adapter`/`--model` do (`sources["complexity.<switch>"] == "cli"`). Each flag only flips its own switch's `enabled` field, so `--routing` alone reuses whatever band table is already configured. Enabling routing or decomposition by flag without scoring on raises the identical prerequisite error the config path raises. `--no-routing` also beats a `--profile` per-effect `routing` pin (#148) — a run-level "off" is authoritative, so a pinned effect doesn't quietly keep routing on. `--last` stashes and replays all three. The TUI's Run view gets matching tri-state (default/on/off) dropdowns for the same switches, so a launch from the TUI behaves identically to the equivalent flags.
