- **Capability consent (#275, #334) now closes two more holes: a fetched
  document named by its cache path, and a `run-library` replay.** A
  `github`-type library source's own cache directory is where its fetched
  subtree lives; naming a cached document by that raw, resolved (symlinks
  followed) path — rather than by the library name `cof run hub/entry`
  resolves — used to look like an ordinary run by path (#284), skipping the
  whole-document gate entirely. CLI, TUI and MCP callers alike now get the
  same gate either way: `circuitry.cli.runtime_shim.run()` classifies the
  resolved `orchestration_path` once, centrally, so a document inside any
  configured refreshable source's cache (`LibraryRegistry.is_cache_path`)
  is treated as fetched content regardless of which string named it — an
  MCP caller naming an absolute path is not the host, and must not be able
  to claim by-path trust just by pointing at the file instead of the name.
  A `cof fetch -o file.yml` copy saved outside the cache is unaffected,
  still trusted per #284, as documented. Separately, replaying a
  `cof run-library` run via `cof run --last` or the TUI Runs view's
  `Ctrl-R` had been skipping the gate since before #334: `run-library`'s
  own `--last` stash now carries its `remote_library_source` classification
  through to the replay, same as `cof run`'s stash already did. See
  `docs/threat-model.md` §9.
