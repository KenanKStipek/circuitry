- **One documented spelling per construct, every spelling still accepted.**
  The DSL surface is canonicalized ahead of corpus generation: `if` (not
  `conditional`), `chain`/`tree` (not `chain_of_thought`/`cot`/
  `tree_of_thought`/`tot`), and one shape for output declarations. The parser
  is unchanged in what it accepts — no orchestration that validated before
  fails now — but the schema descriptions, README, `rules/*.yml`, the wizard
  prime, the orchestration reference, and the curation library all teach
  exactly one form, with deprecated spellings confined to a single
  "also accepted" note per construct.
- **`use.outputs` and `interface.outputs` now take the same shape.** The
  canonical form in both is an object — `summary: {path: prime.summarize.value,
  type: string}` — and the bare-path string shorthand
  (`summary: prime.summarize.value`) is now accepted in both as well, where it
  used to be `use`-only. Previously the two blocks required different syntaxes
  for the same idea, which was the single largest source of authoring errors.
  Both forms normalize to the same `name → path` mapping, and an output that
  is neither now fails with a message naming both accepted forms.
- **Top-level `version` is defined.** It is an optional free-form version
  string for the orchestration document itself (`"1.2.0"`), for the author's
  own tracking — not a schema version, not a feature gate. The runtime reads
  it and ignores it. Numbers are still accepted for back-compat.
