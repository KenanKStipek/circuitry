- **Two more `network`-tagged tools no longer write a local file for a limited document.** `comfyui`'s `image_output` defaults to `path`, which saves the generated image to `image_dir`, and `s3`'s `mode: get` writes the fetched object to `path` when one is given — both under the `network` capability alone, the same gap `http`'s `save_to` closed (#602). A limited document (a library entry, a `use: ref:`/generated-plan child) must now set `image_output: base64` or `image_output: url`, or omit `path` under `mode: get`, written literally where `cof check` can see them; anything else it can see there — the default, a template, or `image_dir` alone — fails `cof check`, and only a `params_json` override of an otherwise-safe literal, or a profile that switches the provider after that check, is caught later, at dispatch. A bundled or library entry that needs to write locally can be ejected (`cof eject <name>`) and run by path instead, which keeps today's behaviour, as does any document run by path directly. electricity doesn't implement either provider yet, so it continues to refuse both with the preview marker regardless.
