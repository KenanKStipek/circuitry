- **`cof check` on a root lists the secrets its `use: path:` children name.** Recursively, as far as the compiler resolves them: a `path:` child inherits its parent's trust, so its own `{secret: ...}` resolves from the root's own `runtime.secrets` exactly as an actual run would, and the root's check now shows it that way, naming the child (`Secrets: billing (host), github (document), named by child.yml`; `--json` adds `secret_children`, the resolved path of every child naming each secret, by name). A secret both the root and a child name is listed once, with `root` and the child both in `secret_children`. A `use: ref:` or `inline:` child is always limited, so it is never walked this way, and one that names a secret is still refused when it actually runs, unchanged. Checking a document on its own keeps today's view, with a one-line hint that a parent running it as a `use: path:` child may still define a secret it shows as not defined.
