- **`electricity-cel`: CEL evaluation for the electricity preview runner.**
  A new crate (`electricity/crates/electricity-cel`) wraps the `cel` crate
  behind Circuitry's own strict/non-strict layer, matching
  `core/cel_eval.py` rather than generic CEL behavior: the `Value` -> CEL
  type mapping (anything with no CEL counterpart, including a bare
  `datetime.date`, becomes `null`; a Python int too large for CEL's
  64-bit `int` raises instead, narrowed to what the expression actually
  reads); heterogeneous equality (`1 == true` is `false`,
  `int`/`uint`/`double` compare across subtype, matching `cel`'s own
  spec-mandated behavior); numeric ordering raising for an `int` on the
  left compared against a different numeric type, matching `celpy`'s
  asymmetric `IntType`-only restriction; the absent-path convention for
  `if`/`while` mode (`evaluate_condition`) — an unset `state.` path makes
  the whole expression `false` with a logged warning, decided by walking
  the parse tree before evaluating, exempt for a `has(...)`-guarded path
  (computed directly against `state`/`value`/`meta`, never by patching a
  clone of them) or under `strict: true`; and `evaluate_expect`'s
  different rule — an unresolved `value`/`meta`/`state` path raises
  instead. The 4096-character cap and the empty-expression/strict-path
  errors reuse Circuitry's own wording word for word (Python's own
  `repr()`, not a bare quote-wrap); `matches()` uses the `regex` crate. A
  differential corpus, generated by actually calling Circuitry's real
  `evaluate_cel`/`evaluate_cel_expect`
  (`electricity/scripts/generate_cel_corpus.py`), is checked in and
  replayed by the crate's tests; CI regenerates it and fails if it
  drifts.

  One finding from that corpus is documented in the crate rather than
  reproduced: naive and aware date-times never actually diverge inside
  CEL — `cel-python` itself defaults a naive `datetime` to UTC the moment
  it is converted, so the naive/aware split is `Value`'s own (Rust-side)
  ordering, not a CEL-layer concern.
