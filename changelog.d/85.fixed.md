- **Loop iteration bindings now survive a nested `dynamic`.** A `dynamic` grouping steps inside a loop body — `loop → dynamic → prompt`, or the `loop → if → dynamic → prompt` shape LLM-generated orchestrations reach for — executed against its own store namespace only, so the iteration binding (`{{item.*}}`), `{{_loop_index}}`, root inputs, and absolute `{{prime.*}}` paths all rendered empty. `cof check` passed and the run "succeeded" with garbage prompts, since only execution could catch it. Loop bodies and conditional branches now hand nested dynamics the same context they render their own children against, layered under the dynamic's store namespace so short sibling paths inside it keep resolving (the nearer node wins a name collision). The same omission in `ConditionalRuntime` meant an `if → dynamic → prompt` lost root inputs even outside a loop; fixed alongside.
