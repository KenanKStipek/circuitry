- **Complexity scores recorded on prompt effect state nodes.** With
  `runtime.complexity.scoring.enabled: true`, every prompt effect's state node
  gains `meta.complexity` — the score, the bounded range it sits in, and the
  per-signal breakdown (raw measurement, weight, normalized value, contribution
  and a one-line note) keyed by signal name. It is written in the same
  pre-dispatch meta block that records the resolved adapter and model, so the
  entry survives a failed effect: a prompt that errors still carries the score
  that explains how hard it was. Because `signals` is a mapping rather than a
  list, an orchestration can branch on its own difficulty from CEL —
  `state.prime.<name>.meta.complexity.score > 60.0`, or on any single signal's
  contribution. With scoring off no key is added at all — not `null`, not an
  empty object — so the state tree is unchanged from a build without the
  feature. Weights configured under `runtime.complexity.scoring.weights` are
  translated to the scorer's signal names, so `prompt_type`, `output_schema` and
  `structural_position` take effect rather than being discarded as unknown
  signals. See [Complexity Configuration](docs/complexity-config.md).
