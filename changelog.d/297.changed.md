- **Migration: a `while` loop's `state.iter.index` no longer runs one pass
  behind.** Before this release, the loop mutated its own context in place,
  so by the time a `mode: cel` condition could read `state.iter.index`, it
  actually saw the *previous* pass's index — a condition had to write
  `state.iter.index + 1 < N` to cap the loop at `N` passes. #242 fixes the
  underlying leak (see `242.fixed.md`): the condition now sees the number of
  passes that have run, correctly, with no off-by-one. Any existing
  condition written to compensate for the old bug — the `+ 1` pattern above,
  or an equivalent like `state.iter.index * step < budget` tuned around it —
  needs the compensation removed: `state.iter.index + 1 < N` becomes
  `state.iter.index < N`. An unmigrated condition still passes `cof check`
  (the change is in runtime meaning, not document validity) but now stops
  one pass earlier than before.
