- **A loop's `collect` no longer drops the last pass or inserts a stray `null`
  for a failed one.** `collected` was assembled by walking `iter_0 ..
  iter_{iteration_count-1}`, where `iteration_count` only counts passes that
  ran to completion — so under `on_error: continue` (either flow) or
  `flow: tree` with `on_error: break`, a failed pass's own `iter_<N>` node
  (value `null`, an error in `meta`) fell inside that range and was collected
  as a stray `null`, while the walk's shortened upper bound dropped the last
  genuinely completed pass instead. `collected` now tracks, as the loop runs,
  exactly which pass indices this run itself completed, and reads only those
  — not the `iter_<N>` keys sitting on the node, which can include an older
  run's passes when the node is reused (a named loop inside an unnamed outer
  loop, or a `--state`/persistence-resumed run). A failed pass is excluded
  entirely — the same contract a disabled collect target already had. The
  loop's `meta.failed_passes` now lists the indices of every pass that
  failed.
