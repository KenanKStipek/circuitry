- **The curl-based adapters now honour a provider's `Retry-After` header.**
  Previously only litellm (whose SDK exceptions carry response headers) could
  supply one, so a 429/503 from openai, anthropic, ollama, watsonx, replicate,
  or an OpenAI-compatible provider always backed off by guess. `run_curl()`
  now captures the header via `--write-out`'s `%{stderr}`/`%header{...}`
  (curl >= 7.84; older curl falls back to the computed backoff cleanly),
  without putting anything on argv or in a temp file, and hands it to the
  structured error `adapters/_retry.py` already builds from curl's exit
  code/stderr.
