- **A loop's `on_error` now also governs the too-long-collection bounds
  check.** An `each` loop whose collection is longer than `max_iterations`
  (with no `each.truncate: true`) used to raise unconditionally, stopping the
  whole run even under `on_error: continue`/`break` — unlike the sibling
  `collection_unresolved` case (an unresolvable `each.in`), which already
  degraded gracefully. `break`/`continue` now record the bound violation on
  the loop's `termination.reason`/`meta.error` (or, for an unnamed loop that
  has neither, a logged warning) and let the run continue; `on_error: fail`
  (the default) still raises.
