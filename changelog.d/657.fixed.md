- CEL's unset-path rule now applies only to the `state.` paths evaluation actually reads: `has()`, `?:`, `&&`/`||` and `all`/`exists` guard a read the way CEL defines them, so `has(state.input.a.b) ? state.input.a.b.c : 'fallback'` and `false ? state.input.x.y : 'fallback'` give `'fallback'` instead of `null`, and `strict: true` raises only for an unset path whose read decides the result. An expression whose unset read doesn't decide the result now reports its other errors instead of being false. A non-boolean operand of `&&`/`||` (`false || 1`) is now an evaluation error instead of that operand's own value, matching CEL and electricity. Same in electricity. (#657)
