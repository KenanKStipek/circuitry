- **`use` composed failures are no longer silently swallowed.** A child effect's own `on_error: skip`/`continue` absorbs its exception at that effect's level, which used to leave the composing `use` node's `meta.error` at `null` with no trace anywhere else in the run — a composed failure was indistinguishable from a healthy result unless a caller happened to also map that specific field through `outputs:`. The `use` node now sets `meta.child_errors` to a list of `{path, error}` for every effect anywhere in the child's tree (any nesting depth, including through further `use:` effects) whose failure was swallowed this way, or `null` when nothing was. Investigated as issue #199's reported hypothesis that a `use:`-composed child re-resolves its config from disk (so a runtime-injected MCP server, adapter, or plugin declared only in the user-level `~/.config/circuitry/config.json` would be invisible to it) — traced every effect runtime (`dynamic`, `conditional`, `loop`, `reflector`, `use`) and added a regression test matching the reported repro; the parent's already-resolved `runtime.*` config is reused verbatim at every nesting depth in the current codebase, so that specific hypothesis did not reproduce. `meta.child_errors` closes the actual observability gap the bug report was chasing regardless of the root cause on the caller's side.
