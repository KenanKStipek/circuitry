- **`electricity` no longer panics (exit 101) when the process environment
  holds a variable whose name or value isn't valid Unicode.** Every
  `std::env::vars()`/`var()` call on the startup path now reads
  `vars_os()`/`var_os()` instead and skips an entry that doesn't decode as
  UTF-8 (only `CIRCUITRY_*` names ever mattered there); `cof` never had this
  problem, since Python decodes `os.environ` with `surrogateescape`.
