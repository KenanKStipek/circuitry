- **`cof check` now catches an `interface.inputs` default that doesn't match
  its declared `type`.** `count: {type: integer, default: "three"}` printed
  `Valid` and then failed inside the first effect that read it; `cof check`
  now names the input, the type and the value — the same rule a
  caller-supplied value is checked against, but without its string
  coercion, since a YAML/JSON default is already a typed value: a quoted
  numeral default (`default: "3"` for an `integer` input) gets a hint to
  remove the quotes rather than being silently accepted. `integer` is a new
  recognized `interface.inputs` type alongside `string`, `number`,
  `boolean`, `array` and `object` — it wasn't checked at all before, so a
  declared-`integer` default could be any value a caller could never
  actually produce. At run time, a default now goes through the exact same
  `type` check a supplied value does, so the mismatch fails at the start of
  the run instead of wherever the bad value happens to land. A declared
  `type` that isn't one of those six is now a `cof check` error too, naming
  the input and the allowed types — it used to be silently unchecked, with
  or without a `default`.
