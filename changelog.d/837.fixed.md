- **A `github` library source now fetches the prompt files its documents reference.** Refreshing a source used to sync only `*.yml`/`*.yaml` files and the manifest, so a document naming a prompt file with another extension (`template: {file: voice.md}`, a declared `prompts:` entry, a message's `content`) would fail once run from the cache — the file was never downloaded. A refresh now also fetches every prompt file one of those orchestrations references, confined to the source's own `path` exactly like a local document's `{file: ...}`. A reference that is missing from the repository, or that would escape the source's own `path`, is skipped rather than failing the whole refresh — it's reported as a warning in the refresh's own output, and the document that names it fails at check or run time instead, the same as a local folder source's own missing file would. A fetched prompt file is never listed as a library entry. Refreshing an unchanged commit still fetches a prompt file a cached document references but that's missing from the cache, so a cache made before this fix works again after one refresh. A changed prompt file still makes a refresh-to-a-new-commit ask for capability consent again.
