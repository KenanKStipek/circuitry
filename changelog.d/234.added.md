- **Tool params by reference.** A leaf anywhere inside a tool effect's `params` (any depth, in objects and lists), `{from: <path>}`, passes the native value at that path — typed, never Mustache-rendered — the same contract as a `use` effect's by-reference `inputs`: the same scope (state namespaces, an enclosing loop's bindings, `prime.<loop>.prev`) and the same compile-time rooting check at `cof check` time. An unresolved path is a hard error naming the param's own path, unless the leaf also carries `default: <value>`. `params_json` stays the way to pass a literal one-key `{from: ...}` object. A security-sensitive param a plugin treats as its own allowlist (the `shell` plugin's `allowed_commands`) never accepts `{from: ...}` — as the whole value or as a list item — at `cof check` time or at run time; only a literal list of strings is honoured there, same as before this change.
