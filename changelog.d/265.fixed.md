- **`cof doctor` now reports the same effective adapter/model `cof run` would actually use.** `doctor_cmd` resolved config via the bare `load_config()`, which never applies `SANE_DEFAULTS`, so a fresh install saw "Effective adapter: None (source: default)" while `cof run` on the same install actually dispatched to `ollama`/`llama3.1:8b`. `doctor` now uses `resolve_config()` like every other command.
- **`cof run --last` now restores `--profile-from-state`** instead of silently dropping it; it was the one override the stash never saved.
- **The TUI's Runs-view replay merges inline `-e` overrides exactly as `cof run` does**, via the same shared `apply_inline_overrides`, instead of a separate implementation that landed an override at the root of an already-namespaced `--state` snapshot — silently unreachable from `{{input.<key>}}`. Replay also now restores the stashed `scoring`/`routing`/`decompose` overrides.
- **`cof run-library` gained flag parity with `cof run`**: `--skip-preflight`, `--profile`, `--scoring`/`--routing`/`--decompose`, `--explain-routing`, and a successful run now stashes for `cof run --last` (as an untrusted document, like any other library asset). `--tail` is also exempt from the auto-`--json` pipe detection now, so `cof run-library <asset> --tail | cat` works the way its own help text ("Ideal for piping") already claimed.
