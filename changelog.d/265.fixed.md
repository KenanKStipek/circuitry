- **`cof doctor` now reports the same effective adapter/model `cof run` would actually use.** `doctor_cmd` resolved config via the bare `load_config()`, which never applies `SANE_DEFAULTS`, so a fresh install saw "Effective adapter: None (source: default)" while `cof run` on the same install actually dispatched to `ollama`/`llama3.1:8b`. `doctor` now uses `resolve_config()` like every other command.
- **`cof run --last` now restores `--profile-from-state`** instead of silently dropping it; it was the one override the stash never saved.
- **The TUI's Runs-view replay merges inline `-e` overrides exactly as `cof run` does**, via the same shared `apply_inline_overrides`, instead of a separate implementation that landed an override at the root of an already-namespaced `--state` snapshot — silently unreachable from `{{input.<key>}}`. Replay also now restores the stashed `scoring`/`routing`/`decompose` overrides.
- **`cof run-library` gained flag parity with `cof run`**: `--skip-preflight`, `--profile`, `--scoring`/`--routing`/`--decompose`, `--explain-routing`, and a successful run now stashes for `cof run --last` (as an untrusted document, like any other library asset). `--tail` is also exempt from the auto-`--json` pipe detection now, so `cof run-library <asset> --tail | cat` works the way its own help text ("Ideal for piping") already claimed.
- **MCP/SDK `validate_orchestration` now uses resolved config.** MCP's `validate_orchestration` tool resolves the same config `run_orchestration` uses, and the public SDK's `validate_orchestration()` gained a `config` parameter, so a document can no longer validate "ok" through MCP/SDK and then fail an allowlist/preflight check that a real run would have caught.
- **An injected adapter (every MCP run, and any SDK call using `adapter=`) now skips only the adapter-reachability check in preflight**, not tool and library-ref preflight too — a broken tool config or bad library ref is caught before any effect runs, the same as the CLI path.
- **`cof setup --json` emits parseable JSON only**; the Rich banner no longer prints unconditionally before the `--json` branch checks the flag.
- **`cof list --help`'s `--category` text now names the real curation categories** (`agents, learn, patterns, recipes, utilities`), generated from the bundled curation index instead of five examples that matched none of them.
- **REST's trigger endpoint returns 400, not 500, for a caller-supplied `orchestration_path` that doesn't resolve** — the same class of error as a missing field, instead of a generic run-failure 500.
- **The SDK's `run_orchestration(out_path=...)` and `run_shared_orchestration(out_path=...)` now write the state file**, matching `cof run --out`; `run()` itself only resolves the path, so embedded callers previously saw `out_path` silently do nothing.
- **MCP's `validate_orchestration` no longer rejects documents that MCP itself runs fine.** Every MCP run injects its own `HostClaudeAdapter` regardless of a document's top-level `adapter:`, and preflight already skipped that adapter's own reachability check for a real run — `validate_orchestration` now does the same (`skip_adapter_check=True`), so `adapter: ollama`/`adapter: openai`/`adapter: cyberdiner` documents that run fine no longer fail validation on a dependency MCP never actually needs. A prompt effect's own `provider:` override is still checked either way, since that one really is built and called at run time.
- **`cof run-library --profile` now writes the profile's `out:`** the same way `cof run` does (`result.out_path`, cli > profile > default) — it previously wrote only an explicit `--out`, so a profile that set `out:` and no `--out` flag silently wrote nothing.
- **`cof run --last` now reapplies a replayed run-library run's `--service-profile`.** The stash previously recorded only `config` and the resolved asset file, so replaying a run that used a service profile silently lost its adapter/model/runtime/plugin overrides; the profile name is now stashed too and reapplied before the replay runs.
- **The TUI's Runs-view replay now restores a stashed `--profile-from-state`**, rebuilding the same `runtime.effective_settings.profile` record `cof run --last` does, instead of silently dropping the profile on replay.
