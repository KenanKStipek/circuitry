- **electricity: one shared nesting-depth limit, so deeply nested input can no longer abort the process.** `electricity-value::MAX_DEPTH` (512) is now the single constant every crate that reads, writes or evaluates nested data shares, rather than each picking its own: `electricity-json`/`electricity-yaml` re-export it (unchanged behavior). `Value`'s `Drop` is now iterative regardless of depth — previously, a `Value` built at run time deeper than `MAX_DEPTH` (not reachable through this workspace's own JSON/YAML readers, which already enforced the limit, but reachable from a CEL evaluation result or any future state merge/loop) could abort the whole process when dropped, rather than merely failing; `Value::depth()` lets a caller check a run-time-built value before `py_str`/`py_repr`/equality/hashing/ordering, which still recurse. `electricity-cel` now pre-scans an expression's combined bracket-and-operator-chain nesting and rejects anything over its own, much smaller `MAX_NESTING_DEPTH` (64) before ever handing it to the `cel` crate's parser — measured directly, an unoptimized debug build of that parser overflowed a 2 MiB thread stack at as few as 12 levels of nested parentheses/brackets, and an arithmetic (`1+1+...`) or sequential-index (`x[0][0]...`) chain overflowed the same stack, in both debug and `--release`, at 1300–1700 terms, well inside the 4096-character expression cap — while chained unary `!` or a long `&&`/`||` chain never came close — and bounds its own `Value` → CEL conversion by the shared `MAX_DEPTH`. `electricity-template` rejects a template whose `{{#section}}`/`{{^section}}` tags nest more than its own `MAX_SECTION_DEPTH` (64) deep at tokenize time: deep section nesting isn't just a stack risk but a CPU-time one, since rendering clones the whole current scope stack on every section, making render time grow with the cube of nesting depth.
