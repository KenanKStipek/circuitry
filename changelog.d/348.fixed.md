- **The `.env` `cof setup` writes is now loaded.** Every host entry point (the `cof` CLI, the TUI, the MCP server, the REST trigger service) loads `~/.config/circuitry/.env` at startup, before config resolution, so an API key entered during `cof setup` actually reaches the adapter — previously nothing ever read the file despite `python-dotenv` being a declared dependency. A real environment variable always wins over the file. Only that one private file is ever loaded, never a `.env` in the working directory or a document's directory, and never automatically by the SDK (`circuitry.api`), which leaves environment ownership to the embedding program. A file not owned by the current user, or writable by group or others, is refused with a warning (`chmod 600 <path>`); a merely group/world-*readable* file still loads, with the same warning `cof doctor` already printed for that case. `cof doctor` now also reports whether the file was loaded and the variable *names* it supplied or skipped — never a value.
