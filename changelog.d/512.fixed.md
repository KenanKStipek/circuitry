- **An unquoted YAML 1.1 date or `!!binary` reaching run state no longer
  crashes `cof run --out`.** A reflector's own parsed plan, a tool's
  `meta.params_rendered`, a `use` effect's literal inputs, and an
  `interface.inputs` default with no declared `type:` (including one nested
  inside an `object`/`array` default) can all carry a
  `datetime.date`/`datetime.datetime`/`bytes` value JSON can't encode on its
  own; `--out`, `--print`, `--live-state`, and the saved state `--resume`
  reads (including every `sqlite`/`postgres`/`mongodb`/`jsonl-file`
  persistence backend) now write it as its string form instead of raising
  `TypeError: Object of type date is not JSON serializable`. electricity
  matches this byte for byte, and now exits nonzero with a clear error on
  stderr if a state still can't be serialized for any other reason, instead
  of writing a `{"error": ...}` placeholder and exiting `0` — on `--out`
  and on the non-TTY stdout summary alike.
