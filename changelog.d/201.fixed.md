- **`use: {path: ...}` composed across directories now resolves.** `_resolve_orchestration`'s documented "parent-orchestration-relative" fallback (also advertised in the error message) read `runtime_config["_orchestration_dir"]`, but nothing in the codebase ever set that key — dead code found while investigating #199. A `path:` (or the deprecated `orchestration:` field) pointing at a file next to the *referencing* orchestration, rather than the process's cwd, failed to resolve whenever a run's cwd differed from that file's own directory — a real-world trap for any project that organizes orchestrations into subdirectories and composes them with relative `path:` values (confirmed repro: `circuits/evaluate-image.yml` with `use: {path: parts/candidates.yml}`, run as `cof run circuits/evaluate-image.yml` from the project root). `_orchestration_dir` is now seeded from the root orchestration file's own directory at the top-level CLI/API load site, and re-derived at each `use:` boundary to the *child's* own directory as composition descends — an inline `use` has no file of its own and simply inherits whatever directory was already in effect. Threaded as a per-child value on the same fresh `runtime_config` copy `#211` introduced for `_use_call_stack`, so it stays race-free across concurrent `flow: tree` siblings.
