- **A prompt's text can be read at dispatch from a file named in state.** A `prompt` effect's `template`, and a message's `content`, accept `file: {from: <state path>}` with a required `within:` directory (a literal absolute path, or `{from: input.<name>}`): the state value is the file's path, resolved against `within`, which the file must stay inside after symlinks are resolved. The file is read once per execution of the effect, before the first attempt, and sent verbatim, never rendered, so a text that contains `{{` survives; the cap is 1 MiB, as for `{file: <path>}`. Each failure (no such file, not a regular file, outside `within`, unreadable, not UTF-8, too large, a state value that is not a string) fails the effect under `on_error`, naming the effect, the field and the path. `meta.template_files` lists one `{field, path, sha256, chars}` per file read, and the file's content is run data, not part of the document hash `--resume` checks. A limited document (a library entry, MCP, REST, a generated plan) can name a literal `within` only inside its project, a document run by path any directory, and a document generated at run time cannot use the form. A `use` child named by `path:` has its parent's trust, and a child resolved through the library is always limited. A reflector's plan prompt cannot use the form (a compile error). Combined with `runtime.state.prompt_sent: sha256`, a prompt built in a file leaves no copy of its text in state. `electricity` supports the same form.
