- **Cross-source `use ref:` with recorded commit pins.** A `use` effect's `ref:` now resolves through the same `LibraryRegistry` as the CLI instead of the curation library alone, so orchestrations compose across sources: **bare** refs (`utilities/critique`) search `runtime.library.sources` in precedence order, **source-qualified** refs (`hub:utilities/critique`) resolve in exactly that source and never fall through. Every resolution against a SHA-pinned `github` source records a **pin** — source, ref, commit SHA, and cache path — into the run state at `runtime.library_refs` (and onto the effect's own `meta.library_ref`), so a later run reproduces the identical tree **offline from cache**; local sources record the resolved path with a null SHA. A ref whose source has never been refreshed now fails at **validate / preflight** time, before any effect runs, with the exact `cof library refresh <source>` command in the message — including refs reached transitively through other orchestrations. Static cycle detection (`cof check`, the TUI Diagnostics view) traverses cross-source refs through their cache paths, so a cycle that closes through a remote source is caught statically. See [`docs/orchestration-reference.md`](docs/orchestration-reference.md#use) and [`docs/library-sources.md`](docs/library-sources.md#referring-to-entries).
