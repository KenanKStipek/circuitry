- **The TUI's Doctor and Settings screens no longer crash the whole app on a missing or broken config.** `load_diagnostics()` now resolves config via `resolve_config()` (the same layered resolution `cof doctor` uses), so a *discovered* broken config — a stale `CIRCUITRY_CONFIG`, an unreadable global or project config file — degrades to a warning instead of raising. An *explicitly* named broken config still raises `ConfigError`, but the Doctor/Settings screens now catch it and show the error in the panel instead of letting it propagate into Textual's message pump and kill the session.
