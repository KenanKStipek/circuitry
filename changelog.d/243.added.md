- **`prime.<loop>.prev.<step>.value`: read the previous pass from inside a
  named loop's body.** Previously a named loop's body had no spelling for
  "the pass before this one" — `{{prime.<step>.value}}` is the current
  (not-yet-written) pass, and `last`/`iter_<N>`/`collected` only resolve
  after the loop completes. `prev` (and `.meta`) works for both `each` and
  `while`, in chain flow; it is absent (not an empty node) on the first
  pass, so a template renders it empty and CEL's `has()` reads false. A
  `flow: tree` body referencing it is a `cof check` error, since tree
  passes run in parallel and there is no previous one. Nested loops: each
  loop's `prev` is its own.
