- **`systemone` tool plugin: typed decisions about a piece of state.** `provider: systemone` calls `POST /v1/systemone` (TypeSafe's hosted API and the local servers that copy it) with `model`, `questions` (`noul`, `choice`, `score`) and a `state` or a `state_file`, and returns the `answers` map as `value`. Every answer is checked against its question before it reaches the document (a missing answer, a type mismatch, an undefined option, probabilities that are not finite, not in [0, 1] or do not sum to 1, a `noul` or `score` out of range); each failure names the question id. The server is a host setting under `runtime.plugins.systemone` (`base_url`, `api_key_env`, `allow_remote`): a limited document cannot change it, only a loopback host is accepted unless `allow_remote` is `true`, and the key is read from the named environment variable and sent only as a bearer token to `base_url`. A redirect is never followed. `state_file` is read at dispatch and must lie inside a required `within` once symlinks are resolved (a limited document's `within` must lie inside its own project), so a long state stays out of saved state; `meta.raw` records `state_sha256` and `state_bytes` instead. 408, 429, 529 and 5xx are retried, honouring `Retry-After`; 400, 401, 413, 415 and 422 are not, and `meta.raw.error_kind` names them. `cof check` rejects a missing `model`, both or neither of `state` and `state_file`, an unknown question type and badly shaped `criteria`. electricity refuses the plugin like the other cof-only plugins. A document with no file of its own (a `use: inline` child, a reflector or decomposition plan, stdin, an SDK string) cannot use `state_file` or name a `within`: a compile error like `{file: …}`'s. An unquoted YAML `true`, `no` or `1` key in `criteria` is checked and sent as the string JSON writes for it. The key is scrubbed from everything the server sends back. See `docs/plugins/systemone.md`.
