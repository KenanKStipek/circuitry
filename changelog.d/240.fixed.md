- **A reflector's planning prompt now sees the run's root `goal` and effective settings.** The `{goal}`/`{context}` slots in the built-in planning prime (`REFLECTOR_PRIME_V1`) read `prime.goal.value` and `runtime.effective_settings` from the `Store` the reflector itself runs in, which holds the reflector's own container (`prime`, or deeper under a loop/dynamic/conditional) rather than the run's root — both slots always rendered empty. They now read `Store.root_state`, the whole-run state dict, regardless of how deep the reflector is nested. `{goal}` is the value of a top-level effect named `goal` (`prime.goal.value`); `{context}` is a concise, redacted summary of `runtime.effective_settings` — `model`, `adapter`, `plugins` — passed through `cli.redaction.redact` and capped at 2000 characters, never the full settings object and never a secret.
