- **Signal tests no longer flake under heavy machine load.** `tests/cli/test_run_sighup.py` and `tests/cli/test_run_cancel_parallel.py` bounded "a cancelled run must stop promptly" at a flat 10-15s, timed against the main thread getting CPU to run its signal handler at all — under enough concurrent load (several full test runs in parallel, `pytest -n` with many workers, or a loaded CI runner) that bound could be too tight even though cancellation itself was working correctly, as confirmed by a stack dump of the stuck process (ordinary `subprocess`/lock waits, not a hang). The bound is now relative to the branch's own sleep length (half of it, at most) rather than a few seconds of wall time, and setup/cleanup waits are more generous, while still proving the same guarantees from #357/#356 (queued branches never start, running children are killed, `finally:` runs in full, a second signal never aborts cleanup, exit codes 130/143/129, `nohup` respected).
