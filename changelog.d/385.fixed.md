- **Ctrl-C, SIGTERM or SIGHUP could be ignored until a running tree-flow branch, parallel-loop pass, or retry backoff finished on its own, instead of stopping it promptly.** POSIX can deliver a signal to any thread that doesn't block it, not necessarily the main thread, but CPython only ever runs the registered handler on the main thread — so any single, unbounded blocking wait on the main thread (or a tree-flow worker thread) deferred that handler until the wait returned on its own, however long that took. `core.dynamic`/`core.loop`'s own branch-completion wait, their post-cancellation wait for an already-killed branch to actually stop, retry backoff, `run_tracked`'s subprocess wait, `python_eval`'s sandboxed-child wait, and `adapters.cyberdiner`'s concurrency-slot wait are now all polled in short slices instead, so a pending signal is noticed within a fraction of a second regardless of which thread it reached, while each step's own timeout is kept exactly. A step a cancellation genuinely cannot reach — an in-flight `mcp` call, the `service` tool's own subprocess calls, or any plain Python-level step — still finishes on its own first, and the run stops once it does, before its own next step starts; a second signal still ends the process at once no matter which thread it lands on. Rarely, and only under very heavy CPU load, the main thread's own handler has been measured running several seconds late (roughly 3% of runs under a synthetic three-process load), during which the run keeps going — any branch still running can reach its own next step first, not only one blocked on a step the kill can't reach; the cause of that multi-second delay isn't pinned down yet, and closing it is tracked as a redesign in #404. A killed shell step whose own command forks a further child at the exact instant of that kill (a shell running more than one command can do this even for a plain sequential pipeline) is now caught by a repeated kill within a fraction of a second, rather than surviving it and running on past the point the run reports itself cancelled.
