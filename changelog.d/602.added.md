- **`http` saves a binary response body to a file: `save_to`.** A 2xx body is written to the named file as raw bytes, never decoded and never kept in state; `value` is `{path, bytes, sha256, content_type, status}` and `meta.raw` has no `body`. The path is relative to the working directory, or to a `within:` directory (literal, or `{from: input.<name>}`), and must stay inside it once symlinks are resolved; missing directories are created. A path outside it, a symlink or directory target, or an existing file without `overwrite: true` fails the effect before any request. `max_bytes` (100 MiB by default) caps the body, and the body goes to a temporary file that is moved into place only once complete, so a failure leaves no partial file. A non-2xx response writes nothing (with `fail_on_error: false`, `value` has a null `path`). It works with `redirects` and secret headers unchanged; `parse` other than `auto` is a `cof check` error. Only a document run by path may name `save_to` or `within`. electricity refuses a document that uses it, with the preview message.
