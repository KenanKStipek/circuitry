- **`cof run --decompose-out <dir>`.** Persists every triggered decomposition's
  generated orchestration to disk, one file per effect, named
  `<run_id>__<effect_path>.yml` — deterministic and collision-free across
  effects, loop iterations, and runs. A written file is the planner's emitted
  YAML verbatim, headed by a comment block naming the run, effect, and outcome,
  and is itself a valid orchestration `cof run` can execute standalone. Plans
  that failed validation or child execution are written too, headed
  `# status: failed` with the recorded error, since those are the ones worth
  reading; the planner-failure and depth-ceiling paths never reach an emitted
  document and have nothing to write. `meta.decomposition` already carried the
  plan — this is a disk-writing layer on top of that existing record, not a
  second copy of it.
