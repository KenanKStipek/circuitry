- **`cof --help`/`cof check` no longer pay for the whole runtime stack just
  to start.** `circuitry`/`circuitry.core`'s package-level re-exports, and
  `cli.app`'s own top-level `runtime_shim`/`tui.wizard_host` imports, pulled
  in `core.compiler` (and its CEL grammar parser, `celpy`/`lark`) and every
  adapter SDK before any command ran. These are now resolved lazily, on
  first use. `cof --help` dropped from ~0.36s real / ~0.31s user to ~0.16s
  real / ~0.13s user (10-run average); `cof check` is unchanged (~0.34s —
  it legitimately compiles the document).
- Dropped the `typer[all]` extra from `pyproject.toml` — it no longer exists
  upstream (`rich`/`shellingham` are typer's own direct dependencies now)
  and raised a "does not provide extra 'all'" warning on every install.
- `learn/hello.yml`'s header comment named a nonexistent invocation path
  (`cof run orchestrations/hello.yml`) instead of the real `cof run
  learn/hello`.
- A tree loop's `on_error: fail` now raises the lowest-index failure
  deterministically, naming the iteration, instead of whichever pass
  happened to finish first with no index at all.
- Corrected the docs/schema for a tree loop's unset `max_concurrency`: it
  is `ThreadPoolExecutor`'s own `min(32, cpu_count + 4)`, not "every
  iteration at once" as documented — unlike a `dynamic` tree's fixed,
  author-declared effect list, `each.in` has no default bound on collection
  size, so a genuinely unbounded default would size the thread pool to
  caller-controlled input.
- An error inside an unnamed loop's or unnamed conditional's body named the
  Python class `LoopDefinition[N]`/`ConditionalDefinition[N]` instead of the
  failing effect's own name.
- `cof score`'s `score_orchestration`/`_walk` (both listed in
  `cli.score.__all__` as public entry points) raised `NameError` when called
  before `cof score` itself had run in the same process — the lazy-loaded
  compiler-chain names they use were only bound inside `score_cmd`.
- `CIRCUITRY_CONFIG` now replaces global/project config resolution instead
  of layering over the global config, matching both the documented
  behavior and `find_config_path`'s own resolution order. As a result, a
  missing or malformed `CIRCUITRY_CONFIG` file is now a hard error (like
  `--config` already was) rather than being silently skipped with a log
  warning.
- `python scripts/build-changelog.py --check` now rejects a changelog
  fragment with a missing or non-numeric `<issue-or-pr>` identifier (e.g.
  `.changed.md`, `some-pr.changed.md`) instead of silently treating it as
  "not a fragment."
- `--live-state`'s temp file now uses `tempfile.mkstemp` (random name,
  `O_CREAT|O_EXCL`) instead of a predictable `<name>.tmp` sibling, closing
  a local symlink-preset window on the first write. A side effect: the file
  is now created mode `0600` (umask-independent) instead of following the
  process umask (usually `0644`), so another local user can no longer read
  it by default.
- MCP `RunManager` now bounds its retention: a cap on concurrent
  non-terminal runs, and eviction of the oldest *terminal* run (never a
  live one) once total retention would exceed its cap. Previously every
  run — and its worker thread — was kept forever.
- REST `x-request-id` is now length-capped and charset-restricted before
  being echoed in the response header or persisted in run state; an
  out-of-shape value gets a fresh UUID instead.
