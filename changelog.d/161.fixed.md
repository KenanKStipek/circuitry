- **Decomposition input inference no longer leaks the `runtime`/`prime` framework namespaces into the planner's source interface.** `_describe_inputs` enumerated every top-level key of an effect's render context to build the `<<< BEGIN SOURCE INTERFACE >>>` block the decomposition planner reads, excluding only `prime` and `_`-prefixed builtins — `runtime` was not excluded. A source template that read only `{{topic}}` could produce a planner prompt listing `inputs: [runtime, topic]`, and the planner dutifully emitted `interface.inputs.runtime: {type: string, required: true}` on the generated orchestration — a phantom input a human would never supply when re-running a persisted plan standalone. `_describe_inputs` now prefers the namespaced `input` root (#86/#155's `input`/`prime`/`runtime` state contract) when present, since only that namespace ever holds genuine caller-supplied values, falling back to the legacy exclude-known-namespaces listing (now also excluding `runtime`) for a context built without the `input` wrapper.
