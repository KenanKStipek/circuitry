- **`scripted` model adapter.** A no-network, deterministic adapter for
  testing orchestrations — the conformance suite's own foundation
  (`electricity/DESIGN.md` §12). It answers every `prompt`/
  `expect: {mode: model}` call from `runtime.adapters.scripted.replies_file`,
  a YAML or JSON file keyed by the calling effect's own state path
  (`prime.review`, `prime.shots.iter_2.describe` — stable across a `flow: tree`
  loop's or dynamic's concurrent branches, unlike call order). A reply is text
  plus token counts, or one of a fixed set of named error kinds that map onto
  the runtime's own retry classification, so retries and fallback chains
  script the same way they do against a real adapter. Replies for one path
  are consumed in order, covering a retry or an `expect:` re-ask against the
  same effect. An unmatched call fails naming the path; replies left unused
  at the end of a run are exposed via `ScriptedAdapter.leftover_replies()`
  for a test harness to fail on, without changing the run's own state. The
  file format is specified in `electricity/docs/spec/scripted-replies.md` so
  electricity's own scripted adapter can read the identical file.
