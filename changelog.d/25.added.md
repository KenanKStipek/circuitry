- **TUI Run view — the run launcher** (`cof tui`, key `2`). Picks an orchestration from the local filesystem (cwd and `./orchestrations/`) or the bundled curation library, reads its `interface.inputs` and generates a typed form (required marker, declared type, `description` as hint, `default` prefilled), validating every value to its declared type before anything launches. Adapter and model dropdowns override resolution for that run only, via the new `RunRequest.adapter_override` / `RunRequest.model_override` fields, which occupy the `cli` tier of `resolve_effective_settings` (so they rank above a profile and above the orchestration's own `adapter`/`model`). The run executes `runtime_shim.run` on a worker thread with `skip_preflight=False`; its `state_observer` is pure — it deep-copies each snapshot and never writes back, so a TUI-driven run ends in the same state as a plain `cof run`. `Ctrl-X` cancels cooperatively through the runtime's ordinary error path. See [`docs/tui.md`](docs/tui.md).
