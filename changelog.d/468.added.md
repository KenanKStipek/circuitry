- **`electricity` loads the user's private `.env` at startup, like `cof`.**
  The `electricity` binary now ports `cli/config.py::load_user_env`: before
  resolving `config.json`, it loads the private `.env` file `cof setup`
  writes next to the global config (`~/.config/circuitry/.env`) into the
  process environment, with the same precedence (a variable already set in
  the real environment always wins), the same refusal of an unsafe file
  (not owned by the current user, or writable by group or others — one
  `WARNING:` naming the `chmod 600` fix), the same softer warning for a
  merely group/world-*readable* file, and the same skip-with-warning for an
  unreadable or undecodable one. Parsing matches `python-dotenv`'s own
  `dotenv_values` exactly: quoting, backslash escapes, the `export ` prefix,
  comments, multi-line values, and `${VAR}`/`${VAR:-default}` interpolation.
  The `electricity` library crate (`circuitry.api`'s own counterpart) never
  loads it — only the binary's own startup does, before every run.
