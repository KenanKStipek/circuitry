- **Adapter plumbing: per-adapter timeouts, litellm's `timeout`, and dead `api_key`/`*_BASE_URL` config advice.** A prompt's per-attempt timeout now resolves `runtime.adapters.<name>.timeout_seconds` for the adapter that attempt actually dispatches to — a `provider:`/`provider_fallbacks` entry sending an attempt to a non-default adapter now honours that adapter's own configured timeout instead of silently running with the run default's. `runtime.adapters.litellm.timeout` is a deprecated (warning-logging) alias of `timeout_seconds`, the spelling every other adapter uses. The OpenAI/Anthropic "set `runtime.adapters.<name>.api_key` in your config" hint is removed — no adapter builder ever read it, and environment variables stay the one documented path for a key. The self-hosted adapters' docstrings no longer claim a `*_BASE_URL` env var (`VLLM_BASE_URL`, `LLAMACPP_BASE_URL`, `LMSTUDIO_BASE_URL`, `TGI_BASE_URL`) that was never read; `runtime.adapters.<name>.base_url` in config.json is the one documented path.
- **Classified retries with backoff and `Retry-After`.** A prompt's `retries` now retries a dispatch failure only when it classifies as retryable — HTTP 429/408/5xx, a timeout, or a dropped connection (curl exit 6/7/28/35/52/56) — and fails the attempt loop immediately on anything else (400/401/403/404/422, a missing key) rather than spending the rest of `max_attempts` on something that cannot succeed. The wait between retries is exponential backoff with full jitter starting from `backoff_ms`, capped at 60s, overridden outright by a provider's own `Retry-After` header when the failing adapter can supply one (litellm can; curl-based adapters can't yet — `--fail-with-body` hides the HTTP status from the exit code, so it's read from curl's own stderr line instead). The default (`retries` unset) is still zero retries.
- **Token accounting for every attempt.** `meta.fallback_attempts` entries now carry their own `tokens_sent`/`tokens_received` (and, for a reply that came back but couldn't be used, a size-capped `raw_reply`), and each node gets new `meta.tokens_sent_total`/`meta.tokens_received_total` fields summing every attempt — failed, retried, and fallen-back-from — across the whole dispatch, not just the winning one. `meta.tokens_sent`/`meta.tokens_received` keep their existing meaning (the winning attempt only). Model-mode `if`/`while` conditions, which bypass `PromptRuntime` entirely, now record their own `tokens_sent`/`tokens_received` on `meta` too.
