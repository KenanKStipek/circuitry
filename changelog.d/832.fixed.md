- **`cof check` now compiles a `use: path:` child the same way a run would.** A child outside its own project boundary (an escaping `{file: ...}`), with a schema error, naming an unknown concurrency group, or failing two `use: path:` levels down, now fails the root's own check — named by its own path relative to the root, with the same error message a run would raise reaching it, in both text and `--json` output — instead of passing the root silently. A failure absorbed anywhere on the path down to it — the failing `use` itself, or an enclosing `use`/`dynamic`/`loop` in the same document or in one above it, under an `on_error` that absorbs a failure anywhere in its own subtree — is a warning instead, since the run swallows it there too; an `if`'s own `on_error` never counts, since it covers only a failed condition, never the branch it takes. A legacy `use: orchestration:` child resolved through the library runs limited in the same walk, confined to its own cached tree, same as the run itself treats it once it falls back.
