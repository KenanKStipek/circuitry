- **`meta.tokens_cached_in`/`meta.tokens_cache_write`.** A prompt effect, the
  `agent` tool, and any other adapter call recorded on a node now carry how
  much of the input the provider served from its own cache (`tokens_cached_in`)
  and wrote to it (`tokens_cache_write`), right after `meta.tokens_received`,
  on both engines. Each is set only when the provider's reply carried that
  count, even when it is 0 — absent, never `null`, otherwise. The two sum
  across retries, fallbacks, decomposition and split parts, and `use`
  children the same way `tokens_sent_total`/`tokens_received_total` already
  do, and `runtime.last_run.totals` gains the same two keys, present only
  when at least one effect reported one.
