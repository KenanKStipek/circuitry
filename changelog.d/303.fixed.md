- **A `.json` orchestration now rejects a repeated key.** `#294` closed this
  gap for YAML; a `.json` document — a file, a library ref, or a `use` child
  loaded by `path:` — still parsed with plain `json.loads`, which silently
  keeps the last of two identical keys. `.json` documents now load through
  a duplicate-key-checking parser that names the key and its path (e.g.
  `effects[0].params`), the same place a YAML document would name the line.
