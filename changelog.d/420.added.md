- **`oscilloscope/` — the `osp` workspace (preview, milestone O-0).** A new
  Cargo workspace (`oscilloscope/Cargo.toml`, `crates/oscilloscope-core`,
  `crates/oscilloscope`) lives alongside `electricity/`, sharing its version
  (`oscilloscope/Cargo.toml`'s `[workspace.package] version` is kept equal
  to `pyproject.toml`'s, same rc mapping as electricity's, checked by the
  same test and the release workflow). `oscilloscope-core` holds the module
  skeleton (`plan`, `observe`, `model`, `diff`, `engine`, `supervise`) that
  milestone O-1 fills in, and depends on `electricity-compiler` and
  `electricity-bytecode` by path. The `osp` binary prints `osp <version>
  (preview)` and the planned `osp <orchestration> [config.json] ...`/`osp
  watch ...` interface; both commands exit 2 with a "not implemented yet"
  message. A new `.github/workflows/oscilloscope.yml` runs fmt, clippy,
  tests and an MSRV check on Linux and macOS, plus a no-publish release
  build, triggered by changes under `oscilloscope/` or
  `electricity/crates/`. `electricity-release-build.yml` is generalized
  into `rust-release-build.yml`, a reusable workflow both electricity and
  osp call; `release.yml` now also builds and attaches `osp`'s preview
  archives to the GitHub release, alongside electricity's — see
  `oscilloscope/README.md` and `oscilloscope/DESIGN.md` (moved from issue
  #418).
