- **An interrupt is never lost.** A signal that arrived while a `dynamic`'s
  own `finally:` ran, right after its body already failed and `on_error:
  continue`/`skip` absorbed that failure, used to be dropped whenever
  nothing ran after that `dynamic` — the run ended `ok: true`, exit 0,
  with no trace the signal ever arrived. The same could happen one level
  further up: a `use`, a `dynamic` with no `finally:` of its own, or a
  loop with `on_error: break` (or `continue` on its last pass) could absorb a nested effect's
  already-settled failure and swallow the pending signal along with it.
  Every one of these now ends the run `ok: false`, exit 130/143/129, on
  both engines, the same way it already did when another effect followed
  the absorbing one. A cleanup step that itself fails after sending the
  signal is now also reported as the interrupt on electricity, matching
  cof. The existing rule stays: with no `on_error` anywhere in the chain,
  the original failure still wins over a later signal (exit 1).
