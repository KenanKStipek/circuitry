- **Configured complexity weights all reach the scorer.** The config surface and
  the scorer named three of the seven signals differently — `prompt_type` /
  `output_schema` / `structural_position` in
  `runtime.complexity.scoring.weights` against `output_type` / `schema_shape` /
  `structure` inside the scorer — so tuning any of those three changed nothing
  and reported nothing: the scorer discarded the unknown name with a warning and
  fell back to its own default. The scorer's signals are renamed to the
  configured names, which are now the only names: one vocabulary shared by the
  config block, the breakdown, `meta.complexity.signals`, and the TUI's
  breakdown pane, with no translation at any call site. The valid names come
  from `circuitry.core.complexity.SIGNAL_NAMES`, which config resolution
  validates against, so the two tables cannot drift apart again. A misspelled or
  stale weight name — including the scorer's three former spellings — fails at
  config resolution with a message listing every valid signal, before the run
  starts.
