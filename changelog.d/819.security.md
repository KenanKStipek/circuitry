- **Every remaining surface that names a configured or requested URL now redacts it, on both engines where both have the surface.** The `runtime.effective_settings` snapshot redactor (`--out`, `--json`, `--live-state`, `last-run.json`) only ever stripped userinfo found directly inside a URL's authority; it now applies the same cut the request-URL redactor uses, catching a credential hidden behind the path, a URL with no scheme at all, and a credential-like query parameter, while keeping its own `***REDACTED***@` marker. `cof`'s verbose progress labels (`adapter · model @ host`) fell back to the raw `base_url` when it had no parseable hostname; `cof doctor`/`cof setup`'s detection table printed the configured URL and urllib's own exception text raw (`cof setup` now reads the real value back from its own field, never from the redacted display text); a library source's fetch errors named `api_base` plus the endpoint raw; the `rss` tool's fetch error named its URL raw; and `comfyui`'s scheme-refusal message echoed the raw `base_url`. All five now redact. A third-party library or SDK's own exception text can echo a URL back, including its userinfo — `webhook`, `web_fetch`, `mcp` and `surrealdb` now scrub any URL found embedded in that text before it reaches a failure message, and a curl-backed adapter's response-body excerpt gets the same scrub.
