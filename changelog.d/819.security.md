- **Every remaining surface that names a configured or requested URL now redacts it, on both engines where both have the surface.** The `runtime.effective_settings` snapshot redactor (`--out`, `--json`, `--live-state`, `last-run.json`) only ever stripped userinfo found directly inside a URL's authority; it now applies the same cut the request-URL redactor uses, catching a credential hidden behind the path, a URL with no scheme at all, and a credential-like query parameter, while keeping its own `***REDACTED***@` marker. `cof`'s verbose progress labels (`adapter · model @ host`) fell back to the raw `base_url` when it had no parseable hostname; `cof doctor`/`cof setup`'s detection table printed the configured URL and urllib's own exception text raw (`cof setup` now reads the real value back from its own field, never from the redacted display text); a library source's fetch errors named `api_base` plus the endpoint raw; the `rss` tool's fetch error named its URL raw; and `comfyui`'s scheme-refusal message echoed the raw `base_url`. All five now redact. A third-party library or SDK's own exception text can echo a URL back, including its userinfo — `webhook`, `web_fetch`, `mcp` and `surrealdb` now scrub any URL found embedded in that text before it reaches a failure message, and a curl-backed adapter's response-body excerpt gets the same scrub. `playwright`'s and `screenshot`'s own page-navigation failures echoed the page URL the same way; their errors are now scrubbed too.
- **The settings-snapshot redactor no longer mangles a string that merely contains an `@` or a link.** Widening it to catch a schemeless credential (the fix above) also made it treat any string with an `@` — an e-mail address, a pinned model id like `name@20240620` — as if it carried a password, and any string with a `://` — a sentence or a multi-line body with a link inside it — as a URL to re-encode. It now only applies that cut to a value shaped like one whole URL token (no whitespace, and either a scheme or a `user:pass@host` shape); everything else passes through unchanged, as it always did. `cof run --last`'s redacted-secret guard, which looked only for an exact `KEY=***REDACTED***` suffix, now also recognizes the marker embedded inside a URL-shaped value (`KEY=http://***REDACTED***@host`) and still refuses to replay it.
- **A URL with no port still carries its password through `InvalidURL`.** `cof doctor`'s backend probes, a library source's fetch, and the `rss` tool's fetch build an URL into a plain `urllib.request.Request` without stripping its userinfo first; a userinfo with no port then reaches `http.client` unstripped and raises its own credential-bearing `InvalidURL("nonnumeric port: ...")`, which escaped the redaction each of these already had for every other kind of failure. All three now strip userinfo before building the request, the same fix the `http` tool and cyberdiner already had, and also catch `http.client.HTTPException` defensively.
