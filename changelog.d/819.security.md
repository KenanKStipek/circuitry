- **One URL redaction rule per engine, applied wherever a URL is named.** A
  value under a URL key (`url`, `base_url`, `api_base`, `endpoint`,
  `expo_url`, `proxy`, or any key ending in `_url` or `_proxy`) in
  `runtime.effective_settings`, `--out`, `--json`, `--live-state` and
  `last-run.json` now loses userinfo hidden after the path, a schemeless
  `user:pass@host` or `token@host` prefix, and credential query values. Only
  those parts change: the rest of the URL is not decoded, re-encoded or
  normalised. A proxy value is always cut at its last `@`. Every other string
  is redacted exactly as before, so e-mail addresses, model ids such as
  `name@20240620`, compact JSON and `mailto:` links pass through unchanged.
  `cof run --last` refuses to replay a stashed value with the marker anywhere
  in it.
- **Fewer places print a URL raw.** cof's verbose progress labels, `cof
  doctor`/`cof setup`'s detection table (`cof setup` still writes the real
  configured value), library-source fetch errors, the `rss` tool's fetch error
  and comfyui's scheme refusal now redact the URL they name. Exception text
  from `webhook`, `web_fetch`, `mcp`, `surrealdb`, `playwright` and
  `screenshot`, and a curl-backed adapter's response-body excerpt, have any
  embedded URL scrubbed.
- **`cof doctor`, library sources and the `rss` tool check a URL before
  fetching it.** A URL whose password contains a `/`, or that has no port,
  used to reach urllib and come back as an `InvalidURL` error showing part of
  the password. They now run the shared `check_url` first, as the `http` tool
  does.
