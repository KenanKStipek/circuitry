- **Every remaining surface that names a configured or requested URL now redacts it, on both engines where both have the surface.** The `runtime.effective_settings` snapshot redactor (`--out`, `--json`, `--live-state`, `last-run.json`) only ever stripped userinfo found directly inside a URL's authority; a value under a URL key (`url`, `base_url`, `api_base`, `endpoint`, `expo_url`, `proxy`, any key ending in `_url` or `_proxy`, at any depth) now gets the same rule the request-URL redactor uses, catching a credential hidden behind the path, a schemeless value with no scheme at all, and a credential-like query parameter, while keeping its own `***REDACTED***@` marker. An ordinary string not under a URL key redacts exactly as it always has: a JWT or API-key-shaped value wholesale, a URL carrying both a scheme and userinfo through its existing cut, everything else untouched — an e-mail address, a pinned model id like `name@20240620`, compact JSON, a `mailto:` link, an image digest and a multi-line body with a link inside it all pass through unchanged. `cof`'s verbose progress labels (`adapter · model @ host`) fell back to the raw `base_url` when it had no parseable hostname; `cof doctor`/`cof setup`'s detection table printed the configured URL and urllib's own exception text raw (`cof setup` now reads the real value back from its own field, never from the redacted display text); a library source's fetch errors named `api_base` plus the endpoint raw; the `rss` tool's fetch error named its URL raw; and `comfyui`'s scheme-refusal message echoed the raw `base_url`. All five now redact. A third-party library or SDK's own exception text can echo a URL back, including its userinfo — `webhook`, `web_fetch`, `mcp` and `surrealdb` now scrub any URL found embedded in that text before it reaches a failure message, and a curl-backed adapter's response-body excerpt gets the same scrub. `playwright`'s and `screenshot`'s own page-navigation failures echoed the page URL the same way; their errors are now scrubbed too.
- **One URL redaction rule per engine, used by every caller that names a URL.** `cof`'s `http_conventions.redact_url(url, marker)` and electricity's `electricity_redaction::redact_url` cut userinfo at the authority boundary (or, when a `:` precedes a later `@`, at that later `@` too — catching a password hidden behind a `/`) and mask a credential-like query value, with nothing else about the URL touched: no percent-decoding, no re-encoding, no case change. A proxy value has no path of its own, so `redact_proxy_value` cuts a later `@` whether or not a `:` precedes it — a token-shaped proxy credential hidden behind a `/`, `?` or `#` (`http://abc/def@proxy:3128`) is cut in full, the same as `main` always cut it. The snapshot redactor and `-e`/stash replay call it with the `***REDACTED***` marker; every refusal, warning and event that names a request URL calls it with the credential dropped outright, exactly as `main` always has. `cof run --last`'s redacted-secret guard, which looked only for an exact `KEY=***REDACTED***` suffix, now also recognizes the marker embedded inside a URL-shaped value or a masked query value (`KEY=http://***REDACTED***@host`, `KEY=https://h/?token=***REDACTED***`) and still refuses to replay it.
- **A URL with no port, or a password hidden behind a `/`, still carried its credential through `InvalidURL`.** `cof doctor`'s backend probes, a library source's fetch, and the `rss` tool's fetch build a URL into a plain `urllib.request.Request` without checking it first; a userinfo with no port, or one hidden behind a `/`, then reaches `http.client` unstripped and raises its own credential-bearing `InvalidURL("nonnumeric port: ...")`, which escaped the redaction each of these already had for every other kind of failure. All three now call the shared `check_url` before building the request, the same check the `http` tool and cyberdiner already had, and also catch `http.client.HTTPException` defensively.
