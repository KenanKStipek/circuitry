- **TUI Run view — the live execution view** (`cof tui`, key `2`). The Run screen now splits into setup on the left and the run itself on the right: an effect tree mirroring the orchestration's structure, drawn from the plan the moment you pick a file and then filled in live from the run's events. Each row carries a status glyph (`·` pending, `◐` running, `✓` done, `✗` failed, `⊘` compiled out), its elapsed time and its `tokens_sent`/`tokens_received`; failures print inline with the `on_error` policy that decided what happened next. Loops grow `iter n` children as they iterate, conditionals collapse to the branch they took, and `flow: tree` siblings show as running together. A footer bar aggregates the run: tokens both ways summed over every effect's `meta`, wall-clock elapsed, and effects finished out of total. Repaints are coalesced onto a 10 Hz tick, so a chatty run never starves the input queue. New `RunRequest.effect_observer` exposes the per-effect completion hook (`(effect_path, effect_node)` — the same payload runtime plugins receive from `on_effect_complete`) to in-process callers alongside, not instead of, configured plugins; `RunSession` forwards it as `on_effect`. The overlay model lives in `circuitry/tui/execution.py` and imports no Textual. See [`docs/tui.md`](docs/tui.md).
