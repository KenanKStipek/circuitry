- **osi: a running prompt's live token figures on the Tape.** The Tape's
  running row reads its own elapsed time and, on a retry, its own attempt
  number first (the row's own column is cut from the right the moment the
  pane is too narrow for all of it): `0.6s · ↓≈41 t · 68 t/s` while a
  streaming adapter answers (the received count marked `≈` until the
  provider reports an exact one, the rate once there's been enough of a
  second delta to measure one), `1.2s · waiting for the first token`
  before the first delta, `1.0s · attempt 2 · waiting for the first
  token` once a retry is under way; a non-streaming adapter keeps only the
  elapsed time and attempt. The token bar and the Totals row draw this
  running estimate in the faint style and add it to the exact total,
  settling to the normal style the instant the prompt finishes, with no
  double counting. The detail pane's own Live block shows First Token,
  Received, Sent and Attempt for a running prompt (`no live figures from
  this adapter` for a non-streaming one). `osi watch` on `--events` alone
  drives the same figures from the latest `progress` line, with no live
  state to read at all -- paired with a plan (`--plan`), or with neither,
  reading the path's own kind from the `progress` line itself. A node
  whose `meta.live` is malformed renders as before, never a crash.
