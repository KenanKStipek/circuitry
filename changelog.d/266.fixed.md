- **Postgres persistence no longer hides its own install hint.** `PostgresStatePersistence.load_latest_state`/`save_run_snapshot` imported `psycopg.sql` ahead of their `try`/`except`, so a missing `psycopg` install raised a raw `ModuleNotFoundError` instead of `_connect`'s actionable "psycopg is required... pip install psycopg[binary]" message. Found while adding execution-path test coverage for the module (was 41%, now 100%) via a mock `psycopg`, plus a real-database counterpart gated behind `CIRCUITRY_POSTGRES_TEST_DSN` and a new `postgres-integration` CI job.
