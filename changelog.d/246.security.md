- **Curl-based adapters no longer echo their command line in error messages.** The Azure OpenAI adapter sent its API key via an `extra_headers` value, which the old masking (keyed on `api_key` alone) never covered, so a failed request leaked the raw key into `meta.error` / `meta.fallback_attempts` — and from there into `--out`, `--print`, `--live-state`, every persistence backend, and REST/MCP responses. Every curl-based adapter (`_openai_compat` and its ~20 consumers, `openai`, `anthropic`, `ollama`, `replicate`, `watsonx`) now reports the adapter, model, target URL (credential-free) and a parsed form of the provider's error body instead of the curl argv, with an `ollama pull` hint on a 404 from Ollama. `meta.error` and `meta.fallback_attempts[].error` are also passed through `redact()` before being stored in run state.
