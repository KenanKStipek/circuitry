- **`service` tool plugin: start, own and stop long-running background
  processes** (#368). `action: start` runs a command in its own process
  group with its output in a log file, refuses a port held by a process it
  did not start (reporting that process's pid, command and working
  directory, and never signalling it), and waits until an `http(s)` URL
  (certificate checks off, for local dev certificates) or a TCP port is
  ready — failing with the tail of the log if the process exits first.
  Ownership records (process group, leader start time, boot time, ports,
  log) are written under a file lock in `runtime.plugins.service.state_dir`
  (default `~/.config/circuitry/services`); a stale record is dropped, and
  a pid now belonging to another process is never signalled. `action: stop`
  sends SIGTERM to the group, then SIGKILL to whatever is left after a grace
  period, waits for the ports to be free, and is idempotent; `action:
  status` reports running, ready and the port holders. Put `action: stop`
  in a `finally:` block to stop a service when the run ends. Needs the
  `shell` and `network` capabilities.
