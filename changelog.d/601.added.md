- **Secrets defined in a document run by path.** A trusted document may define `runtime.secrets.<name>` in its own `runtime:` block (a definition says where to read a secret, never the secret itself), so a project's orchestrations run on a new checkout without editing config.json. Its entries are added to the host's by name instead of replacing the host's whole `runtime.secrets` block, and one with a host secret's name replaces that definition for the run; "Applied host settings" names each as `runtime.secrets.<name>`, never its definition. A `use: path:` child resolves the root document's definitions, and a limited document's `runtime.secrets` is still ignored. `cof check` lists each secret with where it is defined: `host`, `document` or `not defined` (`--json`: `secret_sources`).
