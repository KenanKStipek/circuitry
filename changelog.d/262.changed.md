- **One tool result failure contract.** `ToolResult` gains an `ok: bool`
  field; `ToolRuntime` now sets `meta.error` and applies the effect's
  `on_error` whenever a tool fails, whether the plugin raised or returned
  `ok=False`. `meta.exit_code` now means a process exit code only (binary,
  shell and other process-backed plugins) and is `None` for everything else.
  HTTP-family plugins (`http`, `web_fetch`, `webhook`, `linear`) fail by
  default on a 4xx/5xx response instead of silently succeeding with the
  error body as `value`; each has a `fail_on_error: false` param that
  restores the old always-succeeds behaviour, and the HTTP status now lands
  on `meta.status_code`. Soft-outcome plugins (`wikipedia`, `dns`,
  `port_check`, `validate_yaml`) keep `ok: true` and report their own
  outcome via `value`/`raw` fields — a page not found or a closed port is a
  successful check, not a tool failure. A tool effect's `meta.raw` is now
  populated from `ToolResult.raw` (redacted, size-capped at 64 KiB) for
  every tool effect; prompt effects still never set it. See the `tool`
  effect reference and [Errors](docs/guidebook/05-errors.md).
