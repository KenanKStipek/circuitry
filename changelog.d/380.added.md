- **`electricity-schema`: offline JSON Schema validation for the electricity
  preview runner.** A new crate (`electricity/crates/electricity-schema`)
  validates a document against Circuitry's own `orchestration.schema.json`
  and `profile.schema.json` (Draft 7, via the `jsonschema` crate, which
  already uses `fancy-regex` for `pattern` — no custom regex engine needed,
  and no remote `$ref` fetching, since every ref in Circuitry's schemas is a
  local `#/$defs/...` anchor), reporting the same accept/reject verdict as
  `cof check` and, for every violation, the same location Circuitry's own
  code computes for it (`core.document_check`'s dotted/bracketed
  `json_path`-style location for an orchestration document, `cli.profiles`'
  `/`-joined location for a profile) — the underlying `jsonschema` crate's
  own message text is not required to match Circuitry's Python `jsonschema`
  text word for word, only to be non-empty at the same place; the
  `"{location}: {message}"` wrapping format itself is matched exactly
  (`SchemaError::describe`). `pattern` validation is also aligned with
  Python `re`'s own defaults for the two cases Circuitry's `NamePattern`
  exercises (a trailing `\n` before `$`, a Unicode decimal digit for `\d`),
  and format validation is turned off to match Python's unconfigured
  `Draft7Validator`. The three schema files under
  `electricity/crates/electricity-schema/schema/` are synced byte for byte
  from `src/circuitry/schema/` by `electricity/scripts/generate_schema_copy.py`
  (`--check` in CI); a golden corpus of synthetic valid/invalid orchestration
  and profile documents, generated by
  `electricity/scripts/generate_schema_corpus.py` from Circuitry's own
  `jsonschema.Draft7Validator` run against those same files, is checked in
  and replayed by the crate's tests.
