- **Narrower reference-library ranges.** `pyyaml`, `jsonschema`,
  `jsonschema-specifications`, `referencing`, `chevron`, `python-dotenv`,
  `cel-python`, `lark`, `google-re2` and `pendulum` are now bounded to the
  minor release CI's conformance suite runs against
  (`electricity/scripts/generator-constraints.txt`), instead of an open
  `>=` range — so `pip install circuitry-cof` can no longer resolve a
  library version the suite never ran against.
- **One explicit CEL nesting-depth limit.** A CEL expression (an `if` or
  `while` condition, an `expect:`, the `cel` tool's expression) nested
  deeper than 32 levels is refused with "expression is nested too deeply
  (limit 32)" when it is compiled, before anything evaluates it.
  Parentheses, calls, list/map literals, member-access/index/method-call
  links, binary operators, `&&`/`||` links, prefix `!`/`-`, a ternary and a
  macro's argument each count a level. The limit, the count and the
  message are the same on cof and electricity, whatever the expression's
  shape or the Python version. This replaces cof's old limit (wherever
  CPython's recursion gave out) and electricity's per-shape caps. Because
  every link counts, a run of more than about 30 `&&`, `||` or other
  binary operators (`+`, `==`, ...) is refused too; write
  `x in [a, b, c, ...]` to test many alternatives instead of a long `||`
  chain. A long, flat list or map literal is unaffected: its elements
  don't nest, however many there are.
- **Lists and dicts render as JSON in every template.** A whole list or
  dict inserted by a template renders as JSON text, `["a", "b"]` /
  `{"k": 1}`, instead of Python's repr (`['a', 'b']` / `{'k': 1}`), on cof
  and electricity; nested booleans and nulls follow JSON (`true`, `null`).
  An empty list or dict renders `[]`/`{}` instead of an empty string.
  `{{x}}` still HTML-escapes it where the template escapes; use `{{{x}}}`
  to insert it unescaped. Sections over a list or dict are unchanged.
- **A reflector's `prime_template` renders with Mustache**, not
  `str.format`: write `{{goal}}`, `{{context}}` and `{{max_effects}}`, not
  `{goal}`/`{context}`/`{max_effects}` — the old single-brace form is
  refused at check and compile, naming the fix. A reflector's generated
  plan runs as the model wrote it, never dumped to YAML and reparsed, and
  its `orchestration_sha256` is the sha256 of the plan's canonical JSON
  text, not of any YAML text — sorted by each key's own JSON text (so a
  plan with mixed key types, e.g. a YAML 1.1 `on:` key read as the bool
  `True` beside a string key, still hashes instead of raising). A plan
  that fails to parse as YAML at all now fails the reflector's own
  iteration directly (`parse_failed: ...`, no `generated` child node),
  instead of reaching `use(inline)`'s own validation error.
- **`uniqueItems` compares every pair**, by real JSON equality (numbers by
  value, a boolean never equal to a number, `NaN` never equal to anything,
  deep structural equality for arrays/objects) — never `jsonschema`'s own
  sort-then-compare-neighbours, which can miss a real duplicate a
  merely-tied-but-unequal element separates. The same rule on both `cof`
  and electricity.
- **A `multipleOf` that isn't a number greater than zero** — including
  `NaN`/`Infinity`, which used to pass `jsonschema`'s own metaschema entry
  for it — now makes the schema invalid, checked when the document is
  checked and compiled, wherever one is embedded (a `prompt` effect's
  `schema:`, the `cel` tool's `params.schema`, the `agent` tool's
  `params.result_schema`), with one shared message on both engines.
- **A `$ref` chain is capped at 200 consecutive resolutions** at one
  instance location, on both engines, replacing reliance on Python's own
  variable `RecursionError` threshold (which depends on the call stack's
  own depth, and even on whether a CEL expression has compiled yet in the
  same process) and electricity's own, much larger structural-recursion
  budget. A chain past the cap, or a genuine two-schema `$ref` cycle
  (even one reached only through `allOf`/`anyOf`/`oneOf`/`not`/`if`/
  `then`/`else`/`dependentSchemas`, never a bare `$ref`-to-`$ref` hop),
  fails with one shared message, never a `RecursionError` or a stack
  overflow; a recursive schema that descends into the instance (a tree, a
  list of lists) is unaffected.
- **`cof check` sorts schema errors by `(path, message)`**, not
  `str(err)`, in every place document schema errors are listed — `cof
  check`, a run's own refusal text, an inline `use` child's own
  validation, and the TUI's validate view — on both engines. The path
  itself sorts element by element: a genuine array index numerically
  (`effects[2]` before `effects[10]`), a mapping key — including one
  that merely looks numeric, like a float/bool/date YAML key — by its
  own text.
- **A non-string mapping key in an error's path** (a float/bool/null/date
  YAML key) now renders as the key's own text instead of crashing the
  whole check with `jsonschema`'s own `TypeError`; every other error in
  the same document is still listed. A literal `null` key no longer
  collapses silently either — `jsonschema`'s own `descend` uses `None`
  as its own sentinel for “no path segment,” which used to collide with
  a document key that IS `None`.
- **A `prompt` effect's `schema:` that isn't a well-formed JSON Schema at
  all** (not only a `multipleOf`/`$ref`-chain corner above) is refused
  when the document is compiled, before any model request — previously
  only caught once a reply actually needed validating. The `agent`
  tool's own `params.result_schema` gets the same compile-time check,
  alongside the `cel` tool's `params.schema` and a prompt's `schema:`.
- **The `http` tool, every curl-based adapter and tool (`ollama`,
  `openai`, the OpenAI-compatible family, `anthropic`, `replicate`,
  `watsonx`, `web_search`, `weather`, `comfyui`'s JSON calls), the
  `cyberdiner` adapter, and `systemone` (for a non-loopback `base_url`)
  now decide a proxy themselves**, one rule on both cof and electricity,
  never curl's or urllib's own environment reading: an `http://` URL
  uses `http_proxy`, lowercase only (uppercase `HTTP_PROXY` is never
  read); an `https://` URL uses `https_proxy`, then `HTTPS_PROXY`;
  either falls back to `all_proxy`, then `ALL_PROXY`. `no_proxy` (then
  `NO_PROXY`) is a comma-separated list; `*` bypasses everything, a
  named entry matches a host exactly or as a domain suffix (a leading
  dot is optional), an IP entry matches only that exact IP (never by
  suffix; a bracketed IPv6 entry, `[::1]:8080`, is not supported
  either way), and a `host:port` entry (the host part not itself an
  IP) matches only that host on that exact port — a URL naming no port
  of its own still has one implicitly (80 for `http://`, 443 for
  `https://`), so `example.com:443` matches a portless
  `https://example.com/`. A proxy value with no
  `scheme://` prefix means `http://`; a proxy value naming no port (or
  an empty one) uses port 80 explicitly, never curl's own default of
  1080; userinfo in it, percent-decoded, becomes `Basic` proxy
  authentication whenever a user is present, an empty password
  included; any other proxy scheme is refused. `systemone` never
  proxies a loopback `base_url` at all (its own rule, documented
  separately from the proxy rule above, since it always talks to a
  local service).
  Neither engine reads macOS's (or any OS's) own system proxy settings.
  A proxy that can't be used (an unsupported scheme, an invalid port)
  is refused outright, on every surface and on both engines — never
  silently sent direct instead. A redirect never carries a proxy's own
  credentials onto a hop that isn't proxied.
- **`Retry-After` is parsed per RFC 9110 §10.2.3**, everywhere either
  engine reads it (the `http` tool's own retries, and every adapter's):
  all-ASCII-digits means that many seconds; otherwise it is parsed as a
  *strict* HTTP-date (exactly IMF-fixdate, the obsolete RFC 850 form, or
  asctime, each matched by its own grammar rather than a looser parser
  that would accept more — a missing or different time zone is
  rejected, not guessed at), and the wait is that date minus now, at
  least 0. A sign, a fraction, `inf`/`nan`, whitespace inside, or an
  unparseable date is ignored, and the ordinary exponential backoff
  applies instead — never "wait forever" or a crashed effect (a
  309-or-more-digit value no longer raises `OverflowError` either). The
  usual 60-second backoff cap still applies.
- **A port is parsed strictly wherever a URL is parsed** — the `http`
  tool's own `url`, an adapter's `base_url`, a proxy value — on both
  engines: after the host (or after `]` for an IPv6 literal) comes `:`
  and one or more ASCII digits, 1-65535; an empty port means the
  scheme's own default. Anything else (`+9`, `0_9`, ` 9`, `0`, `65536`,
  non-digits) is refused before any request, naming the URL with any
  userinfo removed.
- **The `http` tool refuses a scheme other than `http`/`https`** —
  before any I/O and before touching any local file, on both engines; a
  curl-based adapter's `base_url` gets the same refusal, since curl
  would otherwise attempt it (a `file://` URL, read as a local file,
  was the sharpest edge here). A redirect target the effect's
  `redirects` setting would actually follow gets the identical refusal,
  whatever its scheme (`file:`, `data:`, not only `ftp:`); one that
  `redirects: never`/`strip_auth` would refuse anyway is refused on
  that mode's own terms instead, never reaching this check.
- **A URL or proxy value containing an ASCII control character or
  whitespace is refused before any I/O**, with one message on both
  engines — the `http` tool's own `url`, an adapter's `base_url`, and a
  proxy value alike.
- **Error text names a URL without its credentials**, on both engines:
  the `http` tool's errors, every adapter's errors and preflight `host:`
  lines, and `cyberdiner`'s, `systemone`'s and `surrealdb`'s errors
  remove any userinfo from the URL they name and mask credential-like
  query values. When an `@` appears after the host, the text names only
  the part after the last `@`.
- **Internal runtime config keys are dropped in one step.** Every key
  starting with `_` is stripped from a run's merged `runtime:` config (the
  user config, the project config, a profile, a document's `runtime:`
  block — trusted documents included — and `-e`) before any internal
  value (`_use_call_stack`, `_decomposition_depth`,
  `_decomposition_planner_path`, `_orchestration_dir`, `_capability_allow`,
  `_library_pins`, ...) is installed, replacing a per-key pop list. A
  trusted document can no longer fake or suppress a recorded `use: ref:`
  pin this way either.
- **Bare sibling references resolve the same way in every container.** A
  bare `{{first.value}}` now resolves at the document root, inside a
  `dynamic` (chain or tree), inside a `use` child's root, in `finally:`,
  and inside a reflector's or a decomposition plan's own root — exactly as
  the dotted `{{prime.first.value}}` form already did at that point: live,
  after `resume: restart`, with saved/resumed state, and in a tree branch's
  snapshot. The scope chain is nearest container first; a loop binding,
  `iter`, `input`, `prime`, `runtime`, an ancestor dynamic's own self-alias
  and every other existing context key keep their meaning, and a loop
  body's/`if` branch's own sibling still shadows an outer name exactly as
  before. "The container's own effects" also includes an unnamed
  (transparent) `if`'s own branches and an unnamed loop's own body, at any
  depth through further unnamed nesting — they write straight into the
  enclosing container's namespace, so a bare reference to one of them
  resolves from anywhere in it, not only from inside the `if`/loop itself.
  `cof check`'s declared-input check no longer flags a bare reference that
  an effect in scope now shadows.

  A nested dynamic's own context is narrower than before this change, for
  every document, including one with no bare reference of its own: it no
  longer merges in the whole of its caller's state (every one of this
  dynamic's own siblings, flattened in as bare top-level names), only its
  own self-alias. A document that happens to rely on that old merge can
  render differently: a built-in key (`_run_id`, `_timestamp`) or a loop
  binding/`iter` inside a nested dynamic whose caller also has an effect or
  binding of that name now gets the built-in/binding's own value, where it
  used to read the caller's effect instead; a bare `{{value}}`/`{{meta...}}`
  inside a nested dynamic no longer reads the *caller* node's own `value`/
  `meta` fields; and a leftover key in the caller's own namespace (from
  `--state`/a resume) that isn't a current effect name is no longer visible
  there at all. The dotted `prime.*` path was never affected either way.
- **`--pretty` keeps the same key order as `json.dumps(sort_keys=True)`
  wherever that already worked** — an all-string dict by text, an all-int
  (or other all-numeric, bools included) dict numerically, exactly as
  before. Only when a dict mixes key types `<` can't compare (a YAML 1.1
  `on:` key read as the bool `True` beside a string key) does it fall back
  to each key's own JSON text, then its type (bool, int, float, null,
  str) as a tiebreak for two keys with the same text — the same order the
  canonical-digest helper already used — instead of raising `TypeError`
  the way a plain `json.dumps(sort_keys=True)` does. A key of a type JSON
  can't write at all (a YAML 1.1 date) still fails, with the same
  `TypeError` `--out` already raises for it, never a `KeyError`.
