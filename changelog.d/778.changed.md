- **Narrower reference-library ranges.** `pyyaml`, `jsonschema`,
  `jsonschema-specifications`, `referencing`, `chevron`, `python-dotenv`,
  `cel-python`, `lark`, `google-re2` and `pendulum` are now bounded to the
  minor release CI's conformance suite runs against
  (`electricity/scripts/generator-constraints.txt`), instead of an open
  `>=` range — so `pip install circuitry-cof` can no longer resolve a
  library version the suite never ran against.
- **One explicit CEL nesting-depth limit.** A CEL expression (an `if` or
  `while` condition, an `expect:`, the `cel` tool's expression) nested
  deeper than 32 levels is refused with "expression is nested too deeply
  (limit 32)" when it is compiled, before anything evaluates it.
  Parentheses, calls, list/map literals, member-access/index/method-call
  links, binary operators, `&&`/`||` links, prefix `!`/`-`, a ternary and a
  macro's argument each count a level. The limit, the count and the
  message are the same on cof and electricity, whatever the expression's
  shape or the Python version. This replaces cof's old limit (wherever
  CPython's recursion gave out) and electricity's per-shape caps. Because
  every link counts, a run of more than about 30 `&&`, `||` or other
  binary operators (`+`, `==`, ...) is refused too; write
  `x in [a, b, c, ...]` to test many alternatives instead of a long `||`
  chain. A long, flat list or map literal is unaffected: its elements
  don't nest, however many there are.
