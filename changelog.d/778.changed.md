- **Narrower reference-library ranges.** `pyyaml`, `jsonschema`,
  `jsonschema-specifications`, `referencing`, `chevron`, `python-dotenv`,
  `cel-python`, `lark`, `google-re2` and `pendulum` are now bounded to the
  minor release CI's conformance suite runs against
  (`electricity/scripts/generator-constraints.txt`), instead of an open
  `>=` range — so `pip install circuitry-cof` can no longer resolve a
  library version the suite never ran against.
- **One explicit CEL nesting-depth limit.** A `mode: cel` expression
  nested deeper than 32 levels (parentheses, calls, list/map/struct
  literals, member-access/index/method-call links, binary operators,
  `&&`/`||` links, prefix `!`/`-`, a ternary and a macro's own argument)
  is refused with "expression is nested too deeply (limit 32)" as soon
  as it is compiled, before any effect evaluates it — the same limit,
  the same depth count and the same message on cof and electricity,
  regardless of the expression's own shape or Python version. Replaces
  cof's old limit (wherever CPython's own recursion happened to give
  out) and electricity's seven separate, per-shape caps. A run of more
  than 32 `&&`, `||` or any other binary operator (`+`, `==`, ...) is
  refused the same as any other shape counts links, not just a deeply
  bracketed one — write `x in [a, b, c, ...]` to test many alternatives
  instead of a long `||` chain. A long, flat list or map literal is
  unaffected: its own elements don't nest, however many of them there
  are.
