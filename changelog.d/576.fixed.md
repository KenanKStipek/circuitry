- **A `parse: json` failure now records `meta.stdout`, `meta.stderr` and `meta.exit_code`**,
  the same raw-output fields a non-zero exit of the same tool already records, also under
  `on_error: continue`, on both engines. Deeply nested stdout no longer lets a `RecursionError`
  escape uncaught; it fails as an ordinary "not valid JSON" parse failure instead, matching
  electricity. `parse: ""` is now treated the same as no `parse` at all, so a template that
  renders empty doesn't fail the effect.
- A `NaN`/infinite float used as a dict *key* (not just a value) now fails `{from: ..., as: json}`
  the same way on electricity as it already did on `cof` (`json.dumps(..., allow_nan=False)`
  rejects a non-finite key too).
- electricity's JSON reader now reports a leading UTF-8 byte-order mark exactly like CPython's
  `json` module does, so a `parse: json` stdout that starts with one fails with the same message
  on both engines.
