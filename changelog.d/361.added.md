- **`electricity-value`: the Python-semantics `Value` type for the electricity
  preview runner.** A new crate (`electricity/crates/electricity-value`)
  defines `Value` — `None`, `Bool`, `Int` (an `i64` fast path with a
  `num-bigint` fallback for Python's unbounded ints), `Float`, `Str`,
  `Bytes`, `List`, an insertion-ordered `Dict` keyed by `Value` itself
  (`indexmap`), `Date`, and `DateTime` (a naive date-time plus an optional
  fixed UTC offset, `chrono`) — every other `electricity` crate will build
  on. Equality and hashing follow Python's dict-key rules exactly (`True`,
  `1`, and `1.0` are the same key and hash equally, including beyond `f64`
  precision; `NaN` is never equal to itself; a naive and an aware
  date-time are never equal; `str` and `bytes` are never equal), and
  ordering is a fallible, Python-style comparison that raises for the same
  pairs Python itself raises for (incomparable types, a naive vs. an aware
  date-time) while leaving `NaN` comparisons simply false, not an error.
  `py_str`/`py_repr` match CPython 3.11's `str()`/`repr()` byte for byte:
  float formatting (shortest round-trip digits, Python's exponent-notation
  cutoffs, `inf`/`-inf`/`nan`), string quoting and escaping (CPython's
  quote-selection rule, `\xNN`/`\uNNNN`/`\UNNNNNNNN` escapes driven by a
  generated Unicode-printability table matching Python 3.11's own Unicode
  Character Database version rather than an independently-versioned
  crate), bytes `repr`, list/dict separators, and `datetime.date`/
  `datetime.datetime` formatting including offsets and microseconds. A
  golden corpus generated from CPython 3.11 (`electricity/scripts/
  generate_value_corpus.py`) is checked in and replayed by the crate's
  tests; CI regenerates it and fails if it drifts.
