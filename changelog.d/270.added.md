- **Opt-in per-step result cache (`cache:`).** `cache: true` (or
  `cache: {ttl: "7d", key: "..."}`) on a `prompt` or `tool` effect — nowhere
  else; `cof check` rejects it elsewhere — reuses a prior successful result
  instead of dispatching again, keyed by a content hash of the effect's
  type, provider/adapter/model, and everything that shapes its result once
  rendered (the rendered prompt/messages and generation params for a
  prompt; the fully rendered params for a tool). A hit skips dispatch
  entirely — no concurrency slot, no retries, no tokens, no plugin call —
  and records `meta.cache: {hit, key, created_at?}`; only a result that
  reached the effect's own success condition is ever stored, never a
  failure (including one `on_error: continue` absorbed). Off by default.
  Stored under a private per-user directory (`~/.cache/circuitry/steps`,
  `0700`/`0600`, written atomically), never in a run's own
  `--out`/`--state`/persistence record. `cof run --no-cache` disables both
  reading and writing it for one run; `cof cache clear`/`cof cache stats`
  manage the store directly.
