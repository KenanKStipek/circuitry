- **`cyberdiner` adapter — wire format now matches expo.** The adapter was speaking snake_case at a camelCase API and reading job fields from the response root instead of expo's `ApiEnvelope`, so every submit came back `HTTP 422 … missing field tierName`. Requests now send `{"prompt": …, "tierName": …}` (and only that — expo's optional `priority` is a future config knob); responses are unwrapped from `data` and read as `jobId` / `status` / `result` / `errorMessage`. Both terminal-success spellings are accepted (`complete`, which cookd's client polls for, and `completed`, which expo's report route writes). `GenerateResult.tokens_received` is populated from `tokensProcessed` — an approximation, since expo counts one figure per job rather than a prompt/completion split — and `raw` now carries `jobId`, `status`, `tierName`, `durationMs` and the full `data` object. A response without the `data` envelope raises a named, actionable error rather than silently yielding an empty completion. The fake-expo unit suite was rebuilt on the real wire shape, including a byte-exact assertion on the submitted request body.
