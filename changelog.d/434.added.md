- **`osp`'s terminal UI.** `osp <orchestration>` and `osp watch <dir>` show
  an interactive terminal UI (`ratatui`/`crossterm`) on a TTY instead of
  the plain-text stream: a header (document, engine, run state, elapsed
  time, effects done out of planned, tokens, the innermost running loop's
  ETA), the plan tree (a status glyph, duration, loop `n/total`, and the
  provider or model in a dim colour), the selected row's own details, and
  a log pane with the same lines as `--log` plus the engine's stderr. The
  engine exiting does not, on its own, end the TUI — it stays on the run's
  final state (ok, failed, cancelled or aborted) until a confirmed `q`, a
  Ctrl-C cancel, or an external INT/TERM/HUP to osp itself (a SIGHUP never
  waits for a key). Keys: `↑↓`/`j`/`k` move, `←`/`→` collapse/expand, `tab`
  switches pane, `f` follows the running row, `e` shows errors only, `/`
  filters, `v` shows a value in full (cycling between the prompt and the
  value when the row has both), `c` cancels with a confirm (the same as a
  confirmed `q`), `q` quits — asking first if a run is going, quitting at
  once with nothing running, and in `osp watch` on a still-going run
  detaching at once with its own distinct ending — Ctrl-C cancels/quits/
  detaches the same way without ever opening or merely dismissing a
  dialog, and `?` shows help. `--log`, or any non-TTY stdout, keeps the
  plain stream unchanged. Raw mode and the alternate screen are restored
  on every exit path: a normal end, osp's own error, a panic, and a
  forwarded SIGINT/SIGTERM/SIGHUP (forwarded to the engine as the signal
  it was). See `oscilloscope/README.md`'s new "The terminal UI" section
  and `oscilloscope/DESIGN.md` §6.3.
