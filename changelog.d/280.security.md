- **Curl command lines no longer leak secrets or request bodies.** Every adapter and tool plugin that shells out to curl (openai, anthropic, ollama, the ~20 OpenAI-compatible providers, replicate, watsonx — including its IAM token exchange — comfyui, web_search, weather) now sends `-q` first (so a local `~/.curlrc` can't silently change behavior), the JSON request body on stdin instead of `-d` argv, and every header — including `Authorization`, `x-api-key`, and provider-specific credential headers — through an inherited pipe fd via `--config` rather than `-H`, so neither a secret nor a request body is ever on argv or in a curl failure message. (The target URL itself was still curl's final argument at the time — #314 later moved it onto the same `--config` channel as headers, so a credential a search API took as a query parameter, or `user:pass@` in a configured `base_url`, is no longer visible in `ps` either; `comfyui`'s one multipart image upload still names the local file path, not its contents, via `-F`.) Tool plugin failure messages (`web_search`, `comfyui`, `weather`) now go through the same shared `curl_failure_message` helper the LLM adapters already used (moved to `circuitry.curl_support` so both can import it), which masks credential-like query-string parameters (e.g. a search API key passed via `extra_params`) and strips userinfo from any URL embedded in the message.
