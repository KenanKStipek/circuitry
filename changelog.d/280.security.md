- **Curl command lines no longer leak secrets or request bodies.** Every adapter and tool plugin that shells out to curl (openai, anthropic, ollama, the ~20 OpenAI-compatible providers, replicate, watsonx — including its IAM token exchange — comfyui, web_search, weather) now sends `-q` first (so a local `~/.curlrc` can't silently change behavior), the request body on stdin instead of `-d`/`-F` argv, and every header — including `Authorization`, `x-api-key`, and provider-specific credential headers — through an inherited pipe fd via `--config` rather than `-H`, so neither a secret nor a prompt/body is ever visible in `ps` or in a curl failure message. Tool plugin failure messages (`web_search`, `comfyui`, `weather`) now go through the same shared `curl_failure_message` helper the LLM adapters already used (moved to `circuitry.curl_support` so both can import it), which also masks credential-like query-string parameters (e.g. a search API key passed via `extra_params`) and strips userinfo from any URL embedded in the message.
