- **A file you run by path is trusted again; documents that arrive another way stay limited.** `cof run ./my.yml`, `cof check` / `cof score` / `cof doctor --orch` on a path, a local file run or validated in the TUI, the SDK's `run_orchestration(orchestration_path=...)` / `validate_orchestration` and `RecurringScheduler` jobs apply the document's whole `runtime:` block and `plugins:` list, as before the host-settings limit: naming the file is the decision to run it. When that includes host settings (any `runtime` key other than `complexity` / `state`, or a `plugins:` entry config does not list), `cof run` prints one line on stderr and `cof check` shows it too, e.g. `Applied host settings from my.yml: runtime.adapters.openai.base_url, plugins: acme.telemetry` — key paths only, never values. A library name (bundled, folder or github source), `cof run-library` / `run_shared_orchestration`, the MCP `run_orchestration` / `validate_orchestration` tools, the REST trigger and generated plans stay limited to `runtime.complexity` / `runtime.state`, with the existing warnings. `run_orchestration`, `validate_orchestration` and `ScheduledJob` take `trust_document=False` to opt a path out; `RunRequest.trust_document` and `validate(trust_document=)` default to `False`. `cof run --last` and the TUI's replay keep the original run's trust. `cof fetch` then `cof run ./file.yml` is running the file by path, so read fetched files first. Project configs still need `cof trust`, and `trust_orchestration_runtime` still trusts every document (now with the same notice).
