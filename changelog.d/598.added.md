- **Secrets for `http` headers and subprocess tools' host `env`, kept out of every record.** Host config `runtime.secrets.<name>` defines a secret as `{keychain: {service, account?}}` (the macOS Keychain, through `security find-generic-password -w`), `{command: [argv...]}` (its stdout, trimmed) or `{env: NAME}`. A document names one as `{secret: <name>}`, with an optional literal `prefix` such as `"Bearer "`, only as a value in an `http` effect's `params.headers` or in a subprocess tool's `runtime.plugins.<name>.env`; it is resolved when the effect dispatches and never appears in `params`, `meta.params_rendered` (which shows `Bearer [secret:<name>]`), `meta.raw`, errors, events or logs, and a response, process output or error that echoes it has it replaced with `[secret:<name>]`. A secret that cannot be resolved fails the effect with an error naming it, never its command's output. Only a document run by path may name one: a limited document, library entry or generated plan that does fails before anything runs, and one written anywhere else, or reaching a header through `params_json` or `{from: ...}`, is refused. `cof check` lists the secrets a document names. `http` gets `redirects: follow | never | strip_auth`: `never` fails on any 3xx, and `strip_auth` follows only to `https`, without `Authorization` or a secret's header to another origin; the default is `strip_auth` when a header came from a secret and `follow` otherwise. electricity implements `redirects` and refuses a document or run that names a secret, with the preview message.
