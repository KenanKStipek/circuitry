- **`run_curl()` works on Windows again.** Windows' `Popen` rejects a
  non-empty `pass_fds` and has no `/dev/fd`, so any header-carrying call
  (effectively every LLM adapter) raised `RuntimeError` there since #311.
  Windows now writes the curl config to a file in the per-user temp
  directory (`%TEMP%`, private to the user by default ACL) and removes it in
  a `finally`; POSIX keeps the inherited-pipe-fd path, never a temp file.
