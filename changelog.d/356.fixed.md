- **Ctrl-C/SIGTERM now stop a parallel step promptly.** A `flow: tree` `dynamic`/parallel `loop` submitted its branches to a `ThreadPoolExecutor`; leaving the `with` block waited for every submitted branch to finish, so every queued branch still ran to completion (then its result was discarded) and a running branch's subprocess kept going until it finished on its own — stopping could take as long as finishing would have. On the first SIGINT/SIGTERM, a branch not yet started is never started (`executor.shutdown(cancel_futures=True)`), and a running branch's child process is killed via its whole process group, not just its own pid — a retry backoff, a concurrency-slot wait, or a worker-thread branch's own next iteration now all observe cancellation too, since a signal only ever interrupts the main thread directly. `finally:` still runs, a cancelled parallel step is still never merged into its parent, and a second SIGINT/SIGTERM while that cleanup is still running ends the process at once with the same exit code and no traceback, instead of escaping as an uncaught exception.
