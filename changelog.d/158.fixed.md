- **Ollama's curl exit-28 (timeout) no longer claims the server is unreachable.** `adapters/ollama.py` treated curl exit 7 (couldn't connect) and 28 (`--max-time` elapsed) identically, so a large local model that needed longer than the timeout to answer got told to run `ollama serve` — actionable advice for the wrong problem. Exit 7 keeps the "start the daemon" hint; exit 28 now names the actual next step: raise `runtime.adapters.ollama.timeout_seconds` or use a smaller/faster model. `runtime.adapters.<adapter>.timeout_seconds` (120s default, resolved generically for every curl-based adapter — ollama, openai, together, perplexity, nvidia_nim, ai21, databricks, and friends) now also has its provenance recorded in `effective_settings.sources`, the same way model/adapter/persistence/complexity already are.
