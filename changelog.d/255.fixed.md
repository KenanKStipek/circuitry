- **The top-level `interface.inputs` contract is enforced everywhere a document runs, not just as a `use` child.** `cof run`, the SDK's `run_orchestration`, the REST trigger, MCP's `run_orchestration`, and the scheduler now all check `required`/`type` through one shared function before anything executes — a missing `required: true` input fails with the same message a `use` child already got, a declared `type` is checked, and a CLI `-e` value or a `use` input rendered through Mustache is coerced to it (number, boolean; JSON for array/object). A declared `type: string` input given a number- or boolean-looking CLI `-e` value keeps the exact text the caller typed (so `-e start=06` stays `"06"`, not the int `6`); a `{from:}`/`-e`/state-file value that resolves to `null` is treated as absent (the `default:` applies, or the key drops) instead of failing the type check. Undeclared extra inputs still pass through unchanged. `interface.inputs` also gains a `default:` key, applied when the caller omits that input, at the top level and for `use:` children alike. A missing `--state` file is now a hard error (`state file not found: ...`) instead of silently running with empty input.
