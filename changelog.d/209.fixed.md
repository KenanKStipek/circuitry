- **`each` loops no longer silently truncate at `max_iterations`.** An `each` loop's collection length is known before the first pass runs, so a collection bigger than `max_iterations` was never a runaway the way an unbounded `while` can be — the runtime used to just process the first `max_iterations` elements and stop, leaving the run green with no record of the unvisited elements. `LoopRuntime` now fails such a loop at start by default, naming both numbers in the error (`each loop 'raster': collection has 144 items but max_iterations is 100 — ...`); set `each.truncate: true` to opt back into the old behavior, which now records `termination: max_iterations_reached` plus `termination.unvisited` on the loop node instead of staying silent. `while` keeps `max_iterations` as its safety floor, but a run that stops because the cap was hit — rather than the condition becoming false — now records `termination: max_iterations_reached` and prints a warning under `--verbose`. Note for anything reading `termination.reason`: the old value for this case was the bare string `"max_iterations"`, now renamed to `"max_iterations_reached"`.
