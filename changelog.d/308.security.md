- **Shell allowlist host pin, REST trigger authentication, private setup files.**
  `shell`'s allowlist can now be pinned host-wide with
  `runtime.plugins.shell.allowed_commands` in config — when set, the effective
  allowlist is that pin intersected with a document's own `allowed_commands`
  (or the tiny default), so a document can only narrow it, never widen it past
  the pin. `allowed_commands` is honoured only from a document's literal,
  unrendered `params` block: a value that arrived via `params_json`, or a
  literal list with an unrendered Mustache tag in it, is now a hard error
  instead of silently accepted, closing a path for model-generated content to
  set its own allowlist. `RestTriggerService` now requires `auth_token` unless
  the embedder explicitly passes `allow_unauthenticated=True` — a falsy token
  used to mean no authentication check at all — and every request's
  `orchestration_path`/`out_path` must resolve inside a new
  `orchestration_root` (the service's working directory by default), refusing
  a path outside it before anything runs. `cof setup` now writes `.env` and
  `config.json` mode `0600` in a `0700` config directory, tightening the mode
  of either file if it already existed looser; `cof doctor` warns on a
  group/world-readable secrets file.
