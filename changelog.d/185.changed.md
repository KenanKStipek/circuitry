- **`mode: cel` now runs real CEL.** The regex→`simpleeval` translator behind `if.expr` and `while.expr` is replaced by [cel-python](https://pypi.org/project/cel-python/), a conforming [CEL](https://github.com/google/cel-spec) implementation, and `cel-python` becomes a core dependency (`simpleeval` is dropped) because CEL is a core language of the DOL. Everything #184 had to reject by name now works: `!` negation, `has()`, the `?:` ternary, the comprehension macros (`all` / `exists` / `exists_one` / `map` / `filter`), the standard function library (`size()`, `int()`, `string()`, `matches()`, `startsWith()`, …), list/map literals and `in`. Equality follows the spec rather than Python, so `1 == true` is `false` while `1 == 1.0` is still `true`; `&&`/`||`/`!` remain the only boolean spellings that parse. Expressions are parsed once and cached by source, so a loop's `while` pays the parser only on its first iteration. `cof check` validates with the same parser — the "known-unsupported syntax" heuristics are gone, and a non-CEL expression is reported as `expression does not parse` naming the effect. Two long-standing translator bugs disappear with it: a `state.x.y` path written *inside a string literal* is no longer rewritten as a state read, and the `state.<input|prime|runtime>` namespace check now reads paths off the parse tree instead of matching a regex over the source. `state` is still the only binding in scope and values are converted into CEL's type system on the way in, so no expression can reach a Python object's attributes or class.
- **`strict: true` on `mode: cel` conditionals and loop `while`s.** By default an unset `state.` path still makes the whole expression `false` and logs a warning naming the path — the disabled-effects contract from #187. Setting `strict: true` beside `mode: cel` turns an unresolved path back into a `CelEvaluationError`, so a condition where a missing field must not silently pick a branch (an order-exit rule, a safety gate) errors the effect and honours `on_error` instead of failing open. A path passed to `has()` is exempt from the absent-state rule anywhere in the expression, so `has(state.prime.x.value) && state.prime.x.value > 1` evaluates properly rather than collapsing to `false`.
- New `learn/cel_showcase` curation orchestration: one branch per CEL construct, including the typed-equality and `strict: true` cases. `cof run learn/cel_showcase -e role=admin -e scores='[10, 0, 95]' -e tier=pro`.
