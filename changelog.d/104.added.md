- **`cof score` — per-effect complexity preview.** Score a whole orchestration
  without running it: `compile_orchestration` freezes the entire effect graph
  before execution, so `cof score <orchestration>` walks that tree and prints a
  table of effect path, score, routing band (when a band table is configured)
  and the signals that dominated the number. `--json` emits the same data
  machine-readably, including each effect's full signal breakdown. Nested
  effects — loop bodies, both conditional branches, a reflector's authored
  prompts — appear under the same dotted paths a profile targets, and
  `--config`/`--profile` preview under exactly the settings a run would use
  (including a profile's disabled effects). The estimate is reported honestly:
  effects that do not exist at compile time — the ones a reflector plans at
  runtime, and a `use` effect's children — are listed as unscoreable *with the
  reason* rather than silently omitted, and the output states that the scores
  are static estimates measured against templates, so a runtime score computed
  against the rendered prompt will be higher wherever a template interpolates a
  large value. The command exits with a clear, actionable message when
  `runtime.complexity.scoring.enabled` is false.
