- **A project config must be trusted before it applies.** A
  `circuitry.config.json` or `config.json` discovered in the working directory
  can set adapter endpoints, tool binaries and environments, MCP server
  commands, persistence targets and runtime plugins, and a cloned repository
  can ship one. It is now applied only after `cof trust`, which shows what the
  file sets, flags the host-sensitive settings and asks first (`--yes` to
  skip); trust is recorded in `~/.config/circuitry/trusted.json` as the file's
  resolved path and SHA-256, so any edit needs trusting again. An untrusted or
  changed file is skipped with one warning naming the file and the command to
  run; the run continues and exit codes do not change. `cof trust --list` and
  `cof untrust` manage entries, and `cof doctor` and the TUI Doctor/Settings
  views show the file's trust state. The global config and files named with
  `--config` or `CIRCUITRY_CONFIG` are always trusted, `cof init` trusts the
  file it writes, and `CIRCUITRY_TRUST_PROJECT_CONFIG=1` trusts every
  discovered file for CI and containers (see `docs/threat-model.md` for the
  risk). **Existing project configs are skipped until you run `cof trust` in
  their directory.**
