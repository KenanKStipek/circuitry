- **`cof` no longer crashes on a `.env` entry it can't set.** A private
  `.env` entry with an empty key, a key containing `=` or a NUL byte (a
  single-quoted key can hold one, e.g. `'A=B'=...`), or a NUL byte in its
  value used to raise an uncaught `ValueError` at startup from every host
  entry point (the CLI, the TUI, the MCP server, the REST trigger service),
  with no indication of which line was at fault. Such an entry is now
  skipped with one warning naming only the key (never the value), and the
  rest of the file still loads; `cof doctor` lists skipped-as-invalid names
  alongside the ones it already reports as supplied or already set.
  Electricity's own port of this loader prints the identical warning line.
