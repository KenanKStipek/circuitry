- **The `agent` tool reads its prompt from a file named in state.** A `tool`
  effect with `provider: agent` accepts `params.prompt: {file: {from: <state
  path>}, within: <dir>}`, the form a `prompt` effect's `template` takes, by
  the same rules: the file is read once per execution, before the first
  attempt (a retry and the repair turn use that text), and sent verbatim to
  the pi or Claude Code session; `within` is required (a literal absolute path
  or `{from: input.<name>}`), the file must stay inside it once symlinks are
  resolved, and a limited document's `within` stays inside its own project.
  No such file, not a regular file, outside `within`, unreadable, not UTF-8 or
  larger than 1 MiB fails the effect under `on_error`, naming the effect,
  `params.prompt` and the path. `meta.template_files` records `{field: "params.prompt",
  path, sha256, chars}` and `meta.params_rendered.prompt` keeps the `{file,
  within}` form, so the text appears nowhere in `--out`, `--live-state` or
  persistence. `params_json` cannot supply the form, and with `params.prompt`
  in the form it must not set `prompt` (its other params still may): `cof
  check` rejects both when the raw `params_json` shows them, and the effect
  fails at dispatch otherwise. A string `prompt` is unchanged. electricity
  compiles the same checks; it does not run the `agent` tool. See
  [A prompt from a file](docs/plugins/agent.md#a-prompt-from-a-file).
