- **`runtime.last_run.document_hash` now uses the same algorithm as the
  capability-consent digest.** `cof run` stamped `document_hash` with its
  own walk over a document's referenced prompt files — concatenating each
  file's bytes directly, with no path label or length between them — so
  moving bytes from the end of one `{file: ...}` prompt source to the
  start of the next left the hash unchanged even though the composed
  prompt text changed. `cof trust`/the consent gate/`use`'s own digest
  already fixed that (tagging each file with its relative path and byte
  length, #398) but `cof run --resume`'s change check kept the old,
  blind-spot algorithm. `document_hash` is now
  `core.prompt_compose.document_content_digest` — the one digest every
  surface uses, computed with the same confinement root the run itself
  resolves for `{file: ...}` references — so it equals the consent digest
  for the same document. A saved state recorded by a release before this
  one still resumes without `--force`: `--resume` also accepts a stored
  hash matching the old algorithm, kept as a private, explicitly
  temporary compatibility fallback — with that old algorithm's own
  blind spot still intact: bytes moved between two referenced prompt
  files go unnoticed.
