- **`agent` tool plugin: a delegated pi or Claude Code session as a tool effect.** `provider: agent` runs one headless coding-agent session with its own tools on, in `cwd`, through the CLI's own login (`engine: pi | claude_code`, default from `runtime.plugins.agent.engine`). The multi-line prompt goes in a temporary file (pi) or on stdin (Claude Code), never in argv; `model`, `thinking` (pi), `permission_mode` and `trust_project_settings` (Claude Code), `tools`/`exclude_tools`, `session` (resume an id), `extra_args`, `env` and `unset_env` shape the call. For Claude Code, `tools` is an allowlist of built-in tools: with `tools` set and no `permission_mode`, the session runs under `dontAsk`, so a call outside the list is denied, and `exclude_tools` is a hard deny in every mode. By default a Claude Code session ignores the repository's own settings (hooks, the API key helper, project MCP servers) and gets the repository root's `CLAUDE.md` appended to its prompt; `trust_project_settings: true` opts out. With `result_file` (+ optional `result_schema`) the agent must write a JSON file: a missing or invalid one gets one repair turn in the same session quoting the errors, and `value` is the parsed JSON; otherwise `value` is the final reply. `meta.raw` records `session_id`, `turns`, `tool_calls`, `tokens`, `cost` (when reported), the path of a compact transcript log and, for Claude Code, `permission_mode`, `project_settings` and `project_instructions`. The session runs in its own process group, so `timeout_ms` or a cancelled run stops everything the agent started. The agent runs with the user's permissions and is not sandboxed; it is tagged `shell`, `fs-write` and `network` for capability consent. See `docs/plugins/agent.md`.
