- **Per-adapter `api_key_env`.** Any keyed adapter's own `runtime.adapters.<name>` block — built-in or an alias's — now accepts `api_key_env`, naming the environment variable to read its credential from in place of the provider's own default: two accounts of the same provider, or a gateway with its own token, can now live in one config. A keyless OpenAI-compatible adapter (`lmstudio`, `vllm`, `llamacpp`, ...) sends `Authorization: Bearer <value>` once it is set. An invalid name is a config error, reported up front the same way a broken alias is. Honoured only from config — an orchestration document's own `api_key_env` is ignored with a warning, regardless of `enabled_adapters`.
