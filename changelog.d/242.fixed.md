- **A `while` loop's `mode: cel` condition can now read `state.iter.index` and
  `state.iter.count` as documented, without the context leak that used to be
  the only reason either one meant anything.** `cof check` already allowed
  `state.iter.index` in a `while` condition, but it was never resolvable on
  its own — the loop set the `iter` binding by mutating its own context in
  place, right before running a pass, and that mutation leaked onto whatever
  dict it was given (fixed by #260 part 1). As a side effect of that leak,
  the *next* check read the previous pass's index, one check behind, so a
  condition written as `state.iter.index + 1 < 3` worked, by accident, as
  "run at most 3 passes" — but only at the root, where the leak landed on
  the run's own state rather than clobbering an enclosing loop's binding.
  `state.iter.index` now resolves on its own, correctly, in every scope: the
  index of the *last finished* pass, `-1` on the check before the first
  pass, `N - 1` once `N` passes have run — the same number the leak used to
  produce, so `state.iter.index + 1 < 3` keeps meaning what it always meant.
  `state.iter.count` is the same count without the `-1` offset (`0` before
  the first pass, `N` once `N` have run) — the recommended, uncompensated
  spelling for new conditions: `state.iter.count < 3` reads the same as
  `state.iter.index + 1 < 3`.
