- **Breaking: orchestration state now has exactly three root namespaces — `input`, `prime`, `runtime` — and old spellings are hard errors, not deprecation warnings.** `input` holds caller-supplied values (CLI `-e`/`--state`, profile `inputs`, `use.inputs`, REST/scheduler `state` payloads, TUI launch forms); `prime` holds effect outputs; `runtime` holds framework metadata. Outside CEL, paths are root-relative (`input.items`, `prime.x.value`); inside CEL, `state` binds to the root (`state.input.items`). Three shapes that used to resolve now fail `cof check`/`validate()` before a run ever dispatches: a loop `each.in` not rooted at `input.`/`prime.`/`runtime.` (bare keys and `state.`-prefixed spellings both error, with the fix-it spelled out); a CEL `state.<key>` where `<key>` isn't one of the three namespaces; and a bare `{{name}}` template ref to a name the document's own `interface.inputs` declares (undeclared bare keys — loop `as` vars, `_loop_index`, sibling shorthand — stay legal). Every caller-state entry point auto-wraps bare root keys under `input` at its own choke point — `runtime_shim._load_state`, persistence hydrate (lift-on-hydrate, logged once), profile `inputs` merge, `use.inputs` child state, and the REST/scheduler `state` payload — so callers on the old bare-key spelling keep working without edits; only orchestration YAML authored against the old grammar needs migrating (`{{name}}` → `{{input.name}}`, `each.in: name` → `each.in: input.name`). A loop whose `each.in` resolves to nothing (missing key, wrong type) now terminates with `collection_unresolved` instead of silently running zero iterations under the `collection_exhausted` reason a genuinely empty list gets.
