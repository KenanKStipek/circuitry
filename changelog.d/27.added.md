- **TUI Runs view — the state inspector and `--last` replay** (`cof tui`, key `4`). Browse a run's state like a filesystem: a collapsible tree over the state dict (`prime` first), each row previewing its value by type, and a detail pane carrying the selected node's dot-path, the `meta` of the effect it belongs to (status, adapter, model, `tokens_sent`/`tokens_received`, created/completed with elapsed, error) and the value in full — verbatim for strings, pretty-printed for structures, which is how a truncated row is expanded. `y` copies the dot-path exactly as a template would write it (`prime.over_items.iter_0.handle.value`), so a value found here pastes straight into `{{…}}`. Three sources feed the same tree: **live** — runs publish snapshots into a store the app owns (not the screen), so a run launched from the Run view keeps updating the inspector after you navigate away, and the view polls rather than blocks, so watching never slows the run; **post-run** — the same store once the run lands; and **file** — a JSON document saved earlier with `--out` or `--live-state`, opened by path, with a written-out error state for a missing, oversized, non-object or half-written file instead of a traceback. `Ctrl-R` replays the last `cof run` from the arguments stashed in `~/.config/circuitry/last-run.json` (now owned by the new `circuitry.cli.last_run`, shared with `cof run --last`) through the same run session the Run view uses — refusing, as the CLI does, to replay a run whose `-e` values were redacted, and never rewriting the stashed `--out`/`--live-state` files. `runtime.effective_settings` is shown exactly as stored, already redacted on the way in. The model lives in `circuitry/tui/inspector.py` and imports no Textual. See [`docs/tui.md`](docs/tui.md).
