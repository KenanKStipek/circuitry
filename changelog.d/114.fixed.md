- **`use` children are no longer invisible to observers.** `core/use.py` built its child `Store` without the parent's `on_write` / `on_effect_start` / `on_effect_complete` callbacks, so every effect inside a `use` — inline or referenced — ran unseen by `--live-state`, the TUI, and every persistence plugin: an orchestration could sit on a single `use` row for minutes with nothing to show for it. The child store now inherits all three, with child effect paths namespaced under the parent's node (`prime.<use>.<child effect>`), composing to arbitrary depth for a `use` inside a `use`. The `use` effect also fires its own start/complete pair, so the child events have a node to nest under and the pairs stay bracketed on every exit path (dry run, child failure, `on_error: skip`/`continue`). Child *state* isolation is unchanged: the child keeps its own store and its explicit `inputs:`/`outputs:` mapping — snapshots mirror the child's effects into a **copy** of the parent's state for observers only, never into the parent's namespace.
- **Whole-run snapshots, not fragments.** `on_write` published whichever subtree the write happened in, so a nested `dynamic` (or a loop body's parallel merge) overwrote `--live-state` with a rootless fragment — the TUI, which looks for `prime`, saw a run with no effects at all. `Store` now carries a reference to the run's root state and every publisher hands observers the whole-run snapshot.
