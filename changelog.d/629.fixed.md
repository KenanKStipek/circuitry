- **CEL error texts.** A missing map key, an out-of-range or wrong-type
  index, indexing a non-container, division by zero and modulus by zero
  are now one line, owned by Circuitry and identical in cof and
  electricity, never a container's contents, a Python tuple repr or a
  Rust Debug dump. The same now holds for an `int`/`uint` overflow, a
  map literal's duplicate or invalid key, selecting a field on something
  that has none, `in` against a type it can't search, and a map key of
  the wrong exact numeric type (an `int`-keyed map probed with a `uint`
  or a `bool` of the same value). An expression nested too deeply to
  parse now fails at validation the same way in both engines too, named
  at its own location, never the raw parser dump or the whole expression
  quoted back.
