- **Size trigger for decomposition.** A second, independent trigger alongside
  the existing complexity-score one: when a prompt effect's rendered input
  strictly exceeds a token budget (`runtime.complexity.splitting`, or the
  effect's own `split.budget_tokens`), the runtime slices its one largest
  state reference deterministically — a list into whole items, a mapping
  into whole entries, text at its own structure — generates a `loop`+`prompt`
  plan (no planner call), runs the parts in parallel, and merges the results
  back at the effect's own path: natively for `text`/array output, through an
  author-supplied `split.merge.template` reduce prompt otherwise. Size is
  checked before the score trigger at the same dispatch seam, and shares its
  record: `meta.decomposition` gains `trigger: "score"|"size"`. `--split/
  --no-split` on `cof run` and the TUI's launch form mirror `--decompose`.
  `cof check` warns when splitting is enabled and a prompt's output type
  needs `split.merge.template` but has none. electricity parses
  `runtime.complexity.splitting` with the same validation, but refuses to run
  a document that enables it or a prompt that sets `split.budget_tokens`,
  with the standard preview marker. See
  [Complexity Configuration → `splitting`](docs/complexity-config.md#splitting).
