- **Loop and effect state hygiene: three related fixes.**
  - A `while` loop no longer writes `_loop_index`/`iter` onto the context it
    was given. It now builds a per-pass overlay the same way `each` already
    does, so a root `while` loop no longer leaks a stray `_loop_index`/`iter`
    into saved state, and a `while` loop nested in another loop's body no
    longer clobbers the outer pass's own `_loop_index`/`iter` for later steps
    in that same pass.
  - `on_error: continue` now nulls an effect's `value` and clears
    result-bearing `meta` left from an earlier pass, in `prompt`, `tool` and
    `use` — matching `on_error: skip`, and the guidebook's documented
    contract that the two are the same leaf-effect degradation. Before this
    fix, a reused node (most commonly an unnamed loop's later pass) could show
    a previous pass's value and `meta` fields (e.g. `retries_used`,
    `decomposition`, a tool's `stdout`/`stderr`/`exit_code`) sitting right
    next to the current pass's `meta.error`.
  - The effect names `value`, `meta`, `input`, `prime` and `runtime` are now
    reserved, alongside the existing `iter_<N>` pattern — in the compiler and
    the schema's name pattern. Each collides with a structural slot the
    runtime itself writes onto a node (`value`, `meta`) or merges into context
    (`input`, `prime`, `runtime`); naming an effect one of these used to
    silently lose its output or shadow a namespace for everything nested
    under it. `cof check` now rejects them, naming the reserved word.
