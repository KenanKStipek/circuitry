- **`cof run --resume`.** Continue an interrupted or failed run of the same
  document from its saved state: `cof run --resume last`, `--resume
  <run-id>` (looked up in the orchestration's configured
  `runtime.persistence` backend), or `--state <file> --resume <anything>`.
  An effect that already finished without error is skipped and its state
  reused — no new adapter/tool call; the first unfinished or failed effect,
  and everything after it in the same chain, reruns — positionally, so a
  later node that merely looks finished (a stale leftover, or one written
  after an absorbed `on_error` failure) reruns too rather than being
  trusted. A named loop in chain flow resumes at its first unfinished pass,
  keeping the finished passes, by its own record of which passes actually
  completed rather than guessing from the saved node. A `flow: tree`
  dynamic's children are each skipped independently. A run interrupted by
  Ctrl-C/SIGINT is caught the same way a crash is, so it leaves a usable
  `--out`/`--last`/persistence record to resume from too (exits `130`).
  Refuses a document that changed since the saved run, or one with no
  recorded content hash at all, unless `--force`; refuses
  silently-inherited inputs on the run-id path unless `-e` names every one
  of them again (#270 — resume part; per-effect `cache:` is a separate
  follow-up).
