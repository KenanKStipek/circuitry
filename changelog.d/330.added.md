- **`cof run --resume`.** Continue an interrupted or failed run of the same
  document from its saved state: `cof run --resume last`, `--resume
  <run-id>` (looked up in the orchestration's configured
  `runtime.persistence` backend), or `--state <file> --resume <anything>`.
  An effect that already finished without error is skipped and its state
  reused — no new adapter/tool call; the first unfinished or failed effect,
  and everything after it, reruns. A named loop in chain flow resumes at
  its first unfinished pass, keeping the finished `iter_<N>` passes. Refuses
  a document that changed since the saved run unless `--force`, and refuses
  silently-inherited inputs on the run-id path unless `-e` passes them
  again (#270 — resume part; per-effect `cache:` is a separate follow-up).
