- **A secret cut off by an excerpt now stays scrubbed.** A subprocess tool's `parse: json` error used to quote `stdout[:200]`, which could leave the first part of a host-`env` secret printed starting just before that cut unscrubbed, since a whole-value scrub of the excerpt alone can no longer find the complete value to replace once it's severed; the scrub now runs on the whole stdout first, on both engines. The same applied to `http`'s error excerpt when a server echoed the token with JSON escapes (a backslash before a literal `/`, or a `\uXXXX` escape of a non-ASCII character): the raw-text scrub now also matches each secret's JSON-escaped forms, and the parsed `error`/`message`/`detail` field the excerpt reads is scrubbed again after decoding, on both engines.
- **Doc fix:** the schema's `params` description for a `{secret: ...}` reference now says it needs a string `secret`, matching the code's own rule (`orchestration.schema.json`, both copies).
