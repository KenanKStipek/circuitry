- **Conformance suite.** `tests/conformance/` runs the Python engine fresh on
  a set of small, model-free documents and compares the result with a
  committed `expected.json` under a shared normalizer (timestamps, run ids,
  durations, and machine-local paths normalized; Circuitry's own error
  messages compared byte-for-byte). Each case names the spec section or
  issue it covers (`spec_case` in its `case.json`).
  `scripts/generate-conformance-cases.py --check` is now part of the
  verification gate and fails when a committed expected state is stale. An
  electricity runner exists alongside it, invoking the `electricity` binary
  per case and skipping with a clear reason when its document uses content
  this preview doesn't support.
