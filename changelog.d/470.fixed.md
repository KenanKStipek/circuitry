- **`--events`: an unnamed `flow: tree` loop's `dispatch` no longer has a
  literal `None` in its `path`, and a `dispatch`/`branch_settled` nested
  inside a tree branch no longer has a path relative to that branch.**
  `Store.fire_concurrent_dispatch` passed an unnamed loop's
  `self.defn.name` (`None`) straight into `effect_path`, whose f-string
  stringified it, landing a path like `prime.None` that named no real
  node — any consumer (oscilloscope included) saw a node that didn't
  exist. Since an unnamed tree loop's passes already run directly in the
  enclosing container (it is transparent, with no node of its own), its
  `dispatch` now carries that container's own path instead — the same
  path every other event it fires already uses; `fire_branch_settled`
  gets the same fallback, used by MCP's `RunManager`. Separately,
  `Store.parallel_branches` reset a tree branch's own path prefix to
  `""` for `start`/`end` nesting but passed `concurrent_dispatch`/
  `branch_settled` straight through unprefixed, so a loop (named or not)
  dispatching from inside another tree loop's branch reported a path
  relative to that branch (`iter_0.inner`) instead of the absolute path
  its own `start`/`end` already use (`prime.outer.iter_0.inner`) — both
  hooks are now wrapped under that prefix the same way. `electricity`
  reproduced the old unnamed-loop behaviour on purpose (#466) and now
  matches; it already composed nested dispatch paths absolutely, so
  nothing needed changing there for the nested case.
